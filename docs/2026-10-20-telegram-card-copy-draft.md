# Telegram 卡片文案草稿

状态：用户已确认采用；2026-10-20 已实现并更新 VPS，通过真实 Telegram 测试。验收见[上线记录](audit/2026-10-20-telegram-plain-cards.md)。下文保留批准时的文案设计。

目标：普通用户先看懂当前结果，需要排查时再打开详情。以下 IP、时间和数量仅为排版示例，不是新一轮线上检查结果。

## 统一写法

- 标题说明页面用途；正文先结果、后数据，通常 4–8 行。列表每项不超过 3 行，说明每页只写一次。
- ✅ 表示该项检查或操作已确认；⚠️ 表示发现具体问题；ℹ️ 表示暂缺记录或未检查。没有记录不用“等待中”的沙漏。
- “未查到”用于查询完成但没有匹配项；“暂时无法查询”用于读取或查询失败；“尚未检查”用于本页没有进行该项检查，三者分开。
- 普通页面使用“告警详情、拦截记录、封禁要求、网站拒绝记录、防火墙名单”。技术详情保留决策、LAPI、nftables、request ID、日志截尾等准确名称。
- 数量带对象和范围：“告警 12 条”“名单内 3 个目标”“网站拒绝 17 次（抽样）”，避免统称“拦截次数”。
- 非模拟是正常情况，不每条重复；模拟项始终标明“模拟”。
- 处置类型按真实数据显示；只有 ban 才叫“封禁”，其他类型显示对应名称或原值。
- 日志有截尾、扫描限制或部分读取失败时，默认页保留一行“记录不完整，详见详情”。精确数量放入详情，不隐藏异常。
- 需要用户行动时才出现“建议”。没有故障时不催促用户反复验收。
- 所有时间标时区；时长可读化，如“3 小时 59 分”，原值在详情中保留。缺失字段写“未记录”或“暂时无法查询”，不猜测。

## 防护概况与综合状态

```text
📊 防护概况 · {主机名}
检测服务：运行中
防火墙服务：运行中
日志解析：正常
当前处置要求：{数量} 条
内存：{已用}/{总量} · 磁盘：{已用}/{总量}
更新：{时间 UTC}
```

服务状态独立展示，不将服务运行汇总成“防护已生效”。详情说明“本页检查服务和配置；实际拦截请查看具体来源的拦截记录”。

异常时第一行改为“⚠️ 需要处理：{最主要的问题}”，下一行给出具体影响或建议；其余异常数量大于零时显示“另有 {数量} 项待处理，查看详情”。

状态写法：停止 → “未运行”；查询失败 → “暂时无法查询”；必需组件缺失 → “尚未配置”；可选组件未启用在默认页省略，详情标“未启用（可选）”；解析样本不足 → “日志解析：样本不足”。

综合状态复用防护概况和机器人摘要，避免重复展示整段诊断说明。详情保存负载、运行时长、各检查项、采样时间及原有排查建议。

## 最近告警

```text
🚨 最近告警 · 最近 5 条

#1983 · 167.94.146.56
类型：{规则名称}
时间：{时间 UTC}
```

每条按钮：“查看 #1983”。空结果：“本次查询未找到告警。”失败：“暂时无法查询告警，请稍后刷新。”

不使用“没有威胁”“突发威胁阻断”等超出记录的结论。

## 告警详情

```text
🔍 告警详情 · #1983
来源：167.94.146.56 · {地区}
类型：{规则名称}
时间：{时间 UTC}
告警处置：封禁 {告警记录时长}
请求样本：GET /{路径}
```

按钮：“拦截记录”“当前封禁要求”“查看详情”。告警附带处置属于历史信息，不写“当前封禁中”或“剩余时间”。无附带处置：“告警处置：未附带处置要求”。模拟告警紧接标题显示“ℹ️ 模拟告警”。

详情保留 ASN、完整规则名、所有现有请求样本与 UA；没有 HTTP 样本写“未记录网站请求详情”。没有告警：“未找到这条告警，请返回列表刷新。”

## 拦截记录

默认卡片分开说明各项结果；不将“名单已加入”合并成“拦截成功”。同 IP 的记录可能对应多个请求，默认标题不用“此告警已拦截”。

有网站拒绝记录：

```text
🔎 拦截记录 · #1982
来源：217.142.187.160
封禁要求：剩余约 4 小时
网站拒绝：已记录 17 次（抽样）
防火墙名单：已加入
防火墙实际拦截：尚未验证
范围：该来源，自 {开始时间 UTC} 起
```

未找到网站拒绝记录：

```text
🔎 拦截记录 · #1983
来源：167.94.146.56
封禁要求：剩余约 4 小时
网站拒绝：本次未查到记录
防火墙名单：已加入
防火墙实际拦截：尚未验证
范围：该来源，自 {开始时间 UTC} 起
```

若抽样覆盖不足，追加“记录不完整，详见详情”。页面不声称一定会自动补出记录。按钮：“刷新”“查看详情”“返回告警”。

| 实际状态 | 默认文字 |
| --- | --- |
| 网站 observed | 网站拒绝：已记录 {次数} 次（抽样） |
| 网站 empty | 网站拒绝：本次未查到记录 |
| 网站 unavailable 或模块读取异常 | 网站拒绝：暂时无法查询 |
| 防火墙 present | 防火墙名单：已加入 |
| 防火墙 absent | 防火墙名单：本次未查到 |
| 防火墙 unavailable | 防火墙名单：暂时无法查询 |
| 防火墙 unsupported | 防火墙名单：当前方式暂不支持查询 |
| 无当前处置要求 | 当前处置：本次未查到 |
| 处置要求查询失败 | 当前处置：暂时无法查询 |
| 非 ban 处置 | 当前处置：{真实类型} · {剩余时长} |

模拟告警紧接标题显示“ℹ️ 模拟告警；以下记录按来源单独查询”。多个处置不只挑选一条冒充全部，显示实际数量并在详情列全本次结果。

详情文字：

```text
📄 拦截详情 · #1983
查询范围：{开始时间} 至 {结束时间} UTC，最多 24 小时
网站拒绝记录：{次数} 条
读取日志：{文件数} 个
日志截尾：{文件数} 个 · 读取失败：{数量}
扫描上限：{未达到 / 已达到}
防火墙名单：{真实查询状态}

网站记录按来源 IP 和时间查询，不一定对应原告警请求。
未查到网站记录时，可能没有新访问、请求先被防火墙拦住，或日志记录不完整。
加入防火墙名单表示封禁配置中存在该 IP，实际丢包尚未验证。
```

有记录时增加最近拒绝时间、HTTP 状态、拒绝原因、未访问业务上游、请求 ID；读取失败时给出固定、安全的排查建议，不输出原始异常。

原因名称：`lapi_ban` → “命中封禁要求”；`lapi_failure` → “封禁查询故障，按策略拒绝”；`appsec_rule` → “命中网站安全规则”；`appsec_failure` → “网站检查故障，按策略拒绝”；`appsec_body` → “请求体检查未完成，按策略拒绝”。原因不同，不全部说成“命中封禁”。

## 封禁列表与处置详情

```text
🚫 封禁列表 · 1/2
本次查到：{数量} 个目标 · {数量} 条处置要求

{IP 或网段}
封禁 · 剩余 {时长}
{数量} 条要求 · 查看详情

范围：本地及手动来源，最多 50 条告警；不含云端情报。
```

多条要求不能把第一条的时长当成全部到期时间；有多条时标“其中一条：封禁 · 剩余 {时长}”。非 ban 类型按实显示。详情列出每条的来源、规则、剩余时间、告警编号及模拟状态。

列表空结果：“本次查询未找到有效处置要求。”指定 IP 无结果：“本次未查到该 IP 的处置要求。可能已到期或不在查询范围内。”不直接说“已解封”。

详情页一次说明：“这里显示处置要求；实际执行情况请查看拦截记录。”按钮：“查看告警”“查看拦截记录”“解封此 IP”“加入日志白名单”。网段不提供仅支持单 IP 的操作。

## 访问分析及三个子卡片

分析入口：“📈 访问分析\n选择要查看的统计。”按钮：“24 小时告警”“可疑来源”“访问路径”。

告警统计：

```text
📈 24 小时告警
告警：{数量} 条
来源 IP：{数量} 个
常见类型：
1. {规则} · {数量} 条
范围：本机告警记录。
```

空结果：“近 24 小时未查到告警。”避免“全网防御战报”“未产生新增威胁”。

可疑来源：

```text
🔎 可疑来源 · 前 10 名
1. {IP} · {数量} 次匹配
范围：最近可读取的网站日志抽样。
```

详情说明按路径或响应状态匹配，不能据此确定恶意身份。空匹配：“本次抽样未匹配到可疑请求。”无可读日志：“暂时没有可读取的网站日志。”

访问路径：

```text
🎯 访问路径 · 前 10 名
1. {路径} · {数量} 次
范围：最近可读取的网站日志抽样。
```

默认不将所有路径称为漏洞或攻击目标。详情保留匹配规则；组合排行复用上述两段并保留范围。

## 容器状态

```text
📦 容器状态 · 1/2
共 {数量} 个，包含已停止的容器

{容器名称}
运行：运行中
健康检查：正常
主配置：与安装记录一致

本页未检查网站访问和实际拦截。
```

状态翻译：running → 运行中；exited → 已停止；restarting → 重启中；paused → 已暂停；created → 已创建；dead → 异常；未知值保留原值供辨认。

健康检查：healthy → 正常；unhealthy → 异常；starting → 检查中；未配置 → 未设置；查询失败 → 暂时无法查询。状态异常时显示具体异常，不合并成笼统“容器正常”。

配置检查：一致 → “主配置：与安装记录一致”；变化 → “⚠️ 主配置：与安装记录不同”；无记录 → “主配置：无本工具安装记录”；读取失败 → “主配置：暂时无法核对”。不将主配置一致写成“Bouncer 已生效”。

详情保留启动时间、Docker 原始摘要及“本页只核对主配置文件，其他接入方式未检查”。无容器：“未找到 Docker 容器。”Docker 查询失败：“暂时无法查询容器，请检查 Docker 服务或权限。”

## 机器人状态

```text
🤖 机器人状态
接收消息：正常
最近成功收取：{时间 UTC}
最近发送成功：{时间 UTC / 尚无记录}
待核对操作：{数量} 项
```

healthy/error/stale/unknown 分别写“正常”“异常”“状态记录已过期”“暂时无法确认”。收取正常不推出发送正常，发送成功指 API 已接受，不声称用户已阅读。

发生错误时显示“⚠️ {收取/发送}：{固定错误分类}”；有退避时显示“下次重试：{时间 UTC}”；无待重试则省略。

待核对操作不省略，追加“请先核对操作结果，再决定是否重试”。详情保留操作 ID、目标、错误分类、状态更新时间和最近成功轮询信息，隐去凭据及原始错误内容。

## 管理工具与白名单

```text
🛠 管理工具
选择操作，执行前会再次确认。
```

按钮：“查看日志白名单”“重载检测服务”“释放文件缓存”。正式产品名 CrowdSec 在确认页或详情保留。

日志白名单：

```text
📋 日志白名单
已登记 IP：{数量} 个
{IP 列表}
作用：在日志检测流程中将这些 IP 加白。
网站检查和云端封禁可能仍然生效。
```

若尚未将原 YAML 安全解析为列表，保留现有文件内容展示，仅更换标题与说明，不虚构 IP 数量。无文件：“未找到本工具管理的日志白名单。”不是全系统无白名单。读取失败：“暂时无法读取日志白名单。”

## 操作确认

封禁确认：

```text
⚠️ 确认封禁？
IP：{IP}
时长：{时长}
将添加封禁要求，执行前会检查管理地址保护。
请在 60 秒内确认。
```

解封确认：“⚠️ 确认解封？\nIP：{IP}\n将删除该 IP 的全部处置要求。防护组件同步后生效。\n请在 60 秒内确认。”

加白确认：“⚠️ 确认加入日志白名单？\nIP：{IP}\n将更新白名单、重载检测服务，并删除该 IP 的全部处置要求。\n网站检查和云端封禁仍可能阻止访问。\n请在 60 秒内确认。”

重载确认：“⚠️ 确认重载 CrowdSec？\n先检查配置，再重载检测服务。\n请在 60 秒内确认。”

缓存确认：“⚠️ 确认释放文件缓存？\n将先写回数据，再释放系统文件缓存。应用占用的内存不一定减少。\n请在 60 秒内确认。”

按钮统一：“确认执行”“取消”。失效：“确认已失效，请重新发起。”取消成功：“已取消，本次未执行。”取消失败或已处理：“此确认已失效或已处理，请先核对结果。”

## 操作结果

| 实际结果 | 文案 |
| --- | --- |
| 封禁要求添加成功 | ✅ 已添加封禁要求\nIP：{IP} · 时长：{时长}\n实际执行情况请查看拦截记录。 |
| 删除处置要求成功 | ✅ 已提交解封\nIP：{IP}\n防护组件同步后生效。 |
| 加白及删除处置要求成功 | ✅ 已更新日志白名单并提交解封\nIP：{IP}\n网站检查和云端封禁仍可能阻止访问。 |
| 重载成功 | ✅ CrowdSec 已重载。 |
| 缓存释放请求成功 | ✅ 已请求释放文件缓存。\n应用占用的内存不一定减少。 |
| 结果不确定 | ⚠️ 操作结果待核对\n请先查询实际状态，再决定是否重试。 |
| 结果记录写入未完成 | ⚠️ 操作记录未保存完整，请先核对实际结果。 |

每条操作结果保留操作 ID。失败按真实阶段表述：“未提交重载”“封禁安全检查未通过，未添加封禁”“加白失败，已恢复原文件”“白名单已更新，但解封失败”等，不能统一成“未执行”。

## 自动告警通知

官方通道单条通知：

```text
🚨 新告警 · #{编号}
来源：{IP} · {地区}
类型：{规则}
告警处置：{类型与时长 / 未附带处置要求}
时间：{时间 UTC}

查看详情：/inspect {编号}
拦截记录需在详情中查询。
```

有请求样本时按现有上限显示路径与客户端；过长时明确省略。模拟告警始终标记。编号不存在时只提示 `/inspect`，不生成无效编号命令。

批量通知：“🚨 新告警 · {数量} 条\n模拟：{数量} 条\n{规则汇总}\n以下展开 {数量} 条，更多记录使用 /inspect 查询。”逐条保留能查询的告警编号；历史处置不标“剩余”。

自定义后台推送使用“🚨 新告警”，去掉“突发威胁阻断”，告警详情复用同一套文字。官方通道仍只负责通知，不假装已在通知生成时查询拦截结果。

## 帮助及通用错误

```text
❓ 使用帮助
查告警：最近告警 → 告警详情
查拦截：告警详情 → 拦截记录
查封禁：封禁列表
做操作：管理工具，或使用下方命令
```

保留当前命令及用法，命令说明使用相同术语。帮助解释“网站拒绝记录”和“防火墙名单”的区别，普通卡片不重复长篇解释。

通用提示：“正在查询…”“正在执行…”“参数格式不正确，请按示例输入”。只读查询失败使用“暂时无法查询，请稍后刷新”；持续失败的详情指向服务或权限检查。不得向聊天输出原始异常、配置文件敏感内容或令牌。

## 实施范围与验收

本草稿覆盖九宫格、所有查询子页、综合状态、拦截卡、自动通知、确认、结果及错误状态。新增“查看详情”用于承载现有技术数据；沿用已有刷新、返回、分页和权限控制。

卡片改名保留旧中文入口别名，斜杠命令和回调协议保持兼容。旧消息不会批量修改；用户刷新或重新打开后显示新版。

验收重点：正常、空结果、查询失败、部分读取、模拟、不同处置类型、多个处置、状态过期和操作结果不确定都有正确文字；HTML 与消息长度有效；不能靠删说明把集合成员说成真实拦截成功，也不能把查询失败说成没有记录。此草稿不改变任何封禁或故障处理策略。
