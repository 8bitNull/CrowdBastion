# 远端 LAPI 与 Bouncer-only 实际验收

2026-10-12，在独立 QEMU TCG 客机中使用官方 CrowdSec 1.8.1（`-no-cs`，仅 LAPI）、Firewall Bouncer 0.0.36、gost 3.3.0、realm 2.9.6。客机 1 vCPU / 1024 MiB，无外网 NIC、无宿主目录共享，快照磁盘；中心与中转为不同网络命名空间。原始结果：[JSON](2026-10-12-remote-bouncer-results.json)。

## 通过的实际检查

| 检查 | 实测 |
| --- | --- |
| gost / realm / NAT × IPv4 / IPv6 × TCP / UDP | 12/12 通过：正常连接、封禁后新会话阻断、DROP 计数增加、正常客户端持续通行、解除后恢复 |
| 安装 helper 生成 `.local` | 真实认证预检通过；基础 YAML 故意使用无效 URL/密钥，官方 Bouncer 读取覆盖后完成整个矩阵 |
| 在线决策过期 | 封禁到期，集合删除，目标客户端恢复 |
| 中心断连期间的短期决策过期 | 集合中决策按期消失，目标客户端恢复 |
| 中心断连，尚未到期的决策 | 目标客户端保持封禁，正常客户端仍可通行 |
| 中心恢复，同步解除 | 目标客户端恢复 |
| Bouncer 重启 | 重新同步已有决策；实测 DROP 计数 0 → 2，正常客户端可通行 |
| LAPI 重启 | 决策流恢复，解除同步并恢复目标客户端 |
| 错误 API 密钥 | 官方 Bouncer 退出码 1，报告 `API error: access forbidden`；没有接受错误凭据 |

这里的断连观测是短时实验，适用于此次官方版本和 nftables 配置。Bouncer 正常停止时会清理其 nftables 表，因此重启重建及重新同步期间不能承诺完全无间隙的防护。中心失联期间无法接收新增或提前解除的决策；本地到期机制与中心同步不同。

## 失败与修正记录

首次运行因 LAPI 监听未就绪导致 Bouncer 连接被拒绝；增加了真实认证就绪检查。第二次矩阵与故障行为已通过，但错误密钥验收逻辑只识别数字状态码，未识别官方 `access forbidden` 文本，错误地判为失败；修正后重新执行。另两次运行主动中断以加强文件隔离和覆盖配置验证，未作为成功样本。最终成功运行及此前各次状态均在 JSON 中记录。

独立审查要求将原认证文件、数据库、数据目录复制到临时目录，并将外层超时清理等待延长到 8 秒，保证内层 3 秒清理完成。已补原文件保持不变与嵌套进程忽略 SIGTERM 的回归测试并通过复审。

## 验证边界

本次中心仅运行真实 LAPI，通过 cscli 创建决策；没有测试从中转 SSH 日志到中心攻击识别的链路。此链路需另行配置可信日志集中采集，详见[运维说明](../remote-bouncer-operations.md)。

这不是两台公网 VPS 的长期运行，也不是 256 MiB 配置、TLS/WireGuard、iptables 后端、arm64 或真实 systemd 首次安装的运行验收。安装事务、发布包校验和 systemd 操作使用隔离模拟测试；官方 Bouncer 与生成配置的网络执行已在客机实测。不能据此推算公网线路吞吐、CPU 容量或防御流量型 DDoS 的能力。

最终代码检查：完整 unittest 共 474 项，457 通过、17 项可选测试跳过；新增远端测试 23/23 通过。ShellCheck（仓库既定排除项）、Bash 语法及 `git diff --check` 通过，独立阶段审查未发现剩余重要问题。没有提交或部署至生产 VPS。
