## 静态管理端口与历史规则解释更正

**此前只读报告对原 IPv4 81 规则漏读了 `!`。** 实际规则始终是 `INPUT ! -i lo ... --dport 81 -j DROP`：拒绝非回环访问，允许回环／SSH 隧道；不是阻止 loopback 的 `-i lo`。历史报告不改写，本报告明确纠正该解释。原始精确输出见[规则复核](2026-11-01-vps179-repair/current-static-rules.json)。

保留原 IPv4:81 规则，新增 IPv4:3000、IPv6:81／3000。现有四条规则均为：

```text
INPUT ! -i lo -p tcp --dport 81   -j DROP
INPUT ! -i lo -p tcp --dport 3000 -j DROP
```

以上各在 IPv4、IPv6 有且仅有一份。`/usr/local/lib/crowdbastion-static-policy/apply.py` 使用 `-C` 查验、缺失才 `-A`；不会回灌整表、flush 链或重建动态集合。`/etc/systemd/system/crowdbastion-static-policy.service` 已启用，排序在 Docker 和 Firewall Bouncer 之前，`systemd-analyze verify` 通过。失败或 INT／TERM 会尝试删除本次新增项；不承诺 SIGKILL、断电或主机故障的事务恢复。

实际重复应用后，标准化后的 IPv4／IPv6 整体规则完全相同，没有重复添加。旧 `netfilter-persistent.service` 为 **active/exited、disabled**：仅取消开机启用，没有 stop 或执行保存整表；iptables／ip6tables 服务别名对应的开机风险同步消除。旧保存文件继续留作证据，不能直接恢复到运行中的 Docker／CrowdSec 防火墙。

四项 `127.0.0.1`／`::1` 的 81／3000 HTTP 均为 200，NPM 内部 loopback API 正常。编码工作区作为外部 IPv4 观察点：80 TCP 可达并返回 HTTP 404，81／3000 均连接超时。该结果验证此观察点的当前管理端口不可达，不证明所有外部网络或未来重启后的情况。VPS 当前没有 global IPv6 地址，未做外部 IPv6 验收。
