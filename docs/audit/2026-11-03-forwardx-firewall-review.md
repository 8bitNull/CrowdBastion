本轮针对[上一批挂链与验收向导改动](2026-11-03-forwardx-firewall.md)进行独立复审、离线复现和修复，范围为仓库代码。**没有 SSH、VPS 部署、生产配置调整、提交或推送。** 原工作区及其既有未提交改动保留，修复先在原隔离副本完成，再按本轮新基线逐文件同步。

## 第一轮：四类已确认问题

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| P1：Docker 启动规范化使远端托管 SHA 失效 | 接入刚成功，后续 owned／状态／修改／移除就可能被当作外部漂移拒绝；启动回滚也缺少标记备份 | 写前检查所有权，受控写入后仅为符合计划的配置更新标记；启动事务同时备份并恢复 `.local`、drop-in 和已有 `.remote.json` |
| P2：远端重新接入只读取基础 YAML | 软件包基础配置变化后，仍生效的自定义覆盖链会在换凭据时丢失 | 使用当前有效配置和已验证的托管覆盖，保留自定义链及其他已有覆盖字段，再更新连接字段 |
| P2：缺省／null 列表与官方语义不一致 | 家族专用链配置会被凭空加 INPUT；合法 null 列表被拒绝 | 缺省和 null 均按空列表；INPUT／FORWARD 等必需路径由对应修复／接入操作明确添加 |
| P2：nftables 验收逐条看 DROP，忽略同链其他规则和计数器身份 | 新增前置 ACCEPT 或替换命名计数器后，计数增长仍可能被误认为原规则阻断证据 | 检查完整所选 hooked 链，未知／放行／跳转规则使该链证据无效；身份绑定链结构、rule handle 和可取得的命名计数器 handle |

初始七项离线探针全部暴露问题：六个断言失败，另一个合法 null 用例被旧实现抛错。没有在宿主机或 VPS 注入防火墙故障。[失败记录](2026-11-03-forwardx-firewall-review/initial-red.log)。

缺省／null 结论来自精确的官方 Bouncer **v0.0.36** 源码：`NewConfig` 未初始化 INPUT；链字段是字符串 slice；固定 `go-cs-lib v0.0.25` 合并器接受 null，`yaml.v2 v2.4.0` 将 null 解为 slice 零值。这里只说明已核对版本，不推断所有未来版本。[固定源码及 SHA 摘要](2026-11-03-forwardx-firewall-review/official-chain-semantics.json)。上一批将 null 当作无效列表的实现与测试，在本轮明确纠正；旧报告和日志保留原样。

## 第二轮：失败路径与修复复审

## 已说明的边界

默认分地址族 nftables 布局及已识别的 iptables/ipset 路径可使用向导；自定义同一 inet 链混合 IPv4／IPv6 规则会保守返回未完成。完全相同规则／计数对象在缺少可用身份信息时被重建，不能仅靠快照可靠区分。外部业务结果和决策操作仍依赖操作者确认，历史通过不改变当前静态健康结论。

q／EOF／Ctrl+C 的中断契约保持；TERM／HUP／SIGKILL 或输出故障不保证生成本轮结论和历史记录。这个已有边界在本轮文档中明确，没有扩展信号退出码接口或声称通用中断恢复。中止后仍需核对短期测试决策退出与业务恢复。

本轮没有公网认证、UDP 后端响应、冷启动或真实攻击封禁验收。维护锁与普通失败回滚不保证断电、强制终止及不遵守锁的特权并发编辑时的原子性。上述边界没有被单位测试通过替代。
