# 2026-11-03 优化事务测试的诊断边界收敛

按用户“继续”推进测试收敛，本轮仅改测试及文档。没有改生产代码、默认 run_shell、测试分层清单、真实超时测试或 VPS，没有提交或部署。

## 定位与改动

四个取消/EOF 场景重复运行完整前置诊断：记录了 186 次 Python 调用，其中健康事件序列化 92 次（2.926 秒）、PyYAML 可用性探测 40 次（1.435 秒）。事务断言原本反复承担健康报告的独立成本。

新增显式夹具入口 `run_optimizer()`，只把前置 check_health_status 替换为记录调用并返回 2（待验证）。10 项事务回归改用此入口；锁、核心依赖、YAML、确认、日志发现、实际配置写入、校验、服务加载与回滚仍运行原代码。调用者 overrides 保留优先级。

四项原有用例继续完整运行 run_shell：取消保持配置、缺少 YAML 仍可诊断/取消、缺少 YAML 停止写入、全部优化项统一加载；独立健康报告、节点引导和其它模块未改。生产检查本身在子 shell 内执行且其结果通过 `|| true` 忽略，因此这个显式单元边界不替代事务条件。
