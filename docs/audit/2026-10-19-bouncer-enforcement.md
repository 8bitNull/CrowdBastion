## 测试方式与边界

当前测试环境的公网 IPv4 出口与 SSH 管理连接来源相同，且没有 IPv6 出站路由。因此使用 VPS 上的临时 network namespace 和 veth，设置独立测试、正常对照地址，通过生产主机的真实 INPUT hook 访问：

- 仅绑定临时私有接口的 TCP、UDP 回显端点，核对实际请求／响应内容。
- 现有 realm 的 `53551`、`56017`、`58372` 端口，分别向主机实际 IPv4、IPv6 地址发起新的 TCP 连接。

IPv4 测试／对照为 `198.19.252.2`、`198.19.252.3`；IPv6 为 `fd7b:cb19:252::2`、`fd7b:cb19:252::3`。预先检查测试前缀与现有非默认路由不重叠，测试源不等于主机或 SSH 管理地址，且没有既有同址决策。

这是真实防火墙执行测试，数据包从 veth 进入本机；没有经过公网物理接口、运营商链路或 CDN。realm 的检查限于 TCP 新连接；UDP 回显没有经过 realm 后端，不代表中转协议、UDP 转发或业务认证验收。

## 实测结果

每个来源每阶段执行 10 项：两个地址族 ×（TCP 回显、UDP 回显、三个 realm TCP 端口）。

| 阶段 | 测试来源 | 正常对照 |
| --- | --- | --- |
| 添加决策前 | 10/10 成功 | 10/10 成功 |
| 决策同步至 Bouncer 后 | 0/10 成功，10 项全部超时 | 10/10 成功 |
| 按 ID 撤销并同步后 | 10/10 成功 | 10/10 成功 |

通过本地 `cscli` 为两个测试地址各添加一条 `2m` ban，唯一原因是 `cbverify-7b39b9d63d`，ID 为 `2205482`、`2205483`。先确认本轮原因、来源、类型、地址与 ID，再执行清理，未按 IP 批量删除其他决策。

封禁期间两个地址均出现在实际 nftables 的 `cscli` 来源集合内；撤销同步后均退出集合。受控探测期间，IPv4、IPv6 对应 DROP 计数各增加 **5 包**，与每族的四个新 TCP 探测及一个 UDP 探测一致；正常对照保持可用。

结论：本轮所测的本机 INPUT 来源 IP 执行链通过，没有复现已同步测试决策仍可建立这些新连接的问题。未将该结论泛化为所有入口、FORWARD、业务协议或攻击检测均已通过。

## 网站执行链与防护边界

通过 `nginx -T` 展开 NPM 磁盘上的配置并读取托管 Bouncer 文件，静态检查得到以下结果。此命令不能单独确认现有 worker 已加载相同版本：

- 全局 `access_by_lua_file` 调用 `/data/crowdsec-1key/access.lua`，使用 `cs.Allow(ngx.var.remote_addr)`。
- `ENABLED=true`、`MODE=live`、`BOUNCING_ON_TYPE=all`，`EXCLUDE_LOCATION` 为空；本轮未发现站点生成配置中的独立 access Lua 覆盖。
- 代理站点配置为使用 `CF-Connecting-IP` 还原来源；本次配置展开中的来源信任没有 IPv4／IPv6 全网通配信任。仅检查这些配置不能证明每条实际代理路径都正确。
- Firewall Bouncer 配置仅执行 `ban` 类型决策，更新周期为 `10s`。决策新增与真实规则同步有时间差。
- **`APPSEC_FAILURE_ACTION=passthrough`**：检测引擎故障时放行。**`APPSEC_DROP_UNREADABLE_BODY=false`**：正文不可读时不强制拒绝。它们是已确认的当前策略；本轮没有故障注入，不能断言某次可疑请求正是因此放行。

通过 CDN 回源时，网络层通常看到 CDN 的源地址；终端用户 IP 封禁依赖 Web Bouncer 使用还原后的地址。CDN 直接命中的缓存不会向 VPS 发起请求，源站 Bouncer 无法独立阻断这部分缓存访问。具体请求需结合 CDN 回源、Nginx 客户端地址和上游处理记录核查。

Bouncer 执行已有决策；是否识别 SSH、网站或中转流量中的某类攻击，由实际采集和检测规则决定。手工 ban 测试通过不能证明 realm 业务攻击自动检测、连接限速或带宽清洗生效。

## 有界日志核对

以当时 10 个当前本地封禁 IP 对照 33 个 NPM 访问日志，每文件最多读取末尾 64 KiB，共检查 2080 行，找到 273 行同址历史记录。最近一小时窗口没有取得可关联的合格样本，因此本次日志检查不足以判断某个已封禁 IP 是否仍被网站放行，也不能据此宣称没有漏防。没有把单独出现访问日志或 HTTP 403 当作成功访问。

确定具体漏防仍需可疑 IP、发生时间、域名或中转端口，并区分“未产生决策”与“决策已生效仍能访问”。本轮未取得该具体实例。
