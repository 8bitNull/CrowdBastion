# ForwardX 场景：挂链去重与 iptables/ipset 验收向导

用户确认 VPS144／VPS82 经验对应的脚本改进后，本批落实前两项优先工作：**统一 Bouncer 挂链生成，补齐默认 iptables/ipset 后端的入口验收及完整生命周期向导。** 资源推荐、系统生命周期／sysctl 诊断、开机恢复分类和软件包安装恢复属于后续批次，本次没有将其描述为已实现。

## 最终行为

官方 Bouncer 对通用链列表与地址族列表采用叠加语义。配置生成现在保留二者的有效自定义链、按地址族去重，并输出 `iptables_chains: []` 以及各自的 IPv4／IPv6 列表，避免同一入口被重复挂链。启动修复、迁移快照、本地凭据配置、远端接入和状态展示共用这项语义；保留带点号的有效自定义链名。无效列表在配置写入前拒绝，迁移也会在准备事务前拒绝无效列表。基础软件包 YAML、凭据和已有无关字段保持。

例如通用 `[INPUT, COMMON, INPUT]`、IPv4 `[V4, INPUT]`、IPv6 `[V6]`，补齐 INPUT／FORWARD 后有效列表为 IPv4 `[INPUT, COMMON, V4, FORWARD]`、IPv6 `[INPUT, COMMON, V6, FORWARD]`，不丢 COMMON，也不重复 INPUT。本地凭据配置中专属 IPv4 的 DOCKER-USER 不会因规范化复制到 IPv6；启动修复仍保留项目原有的 Docker 双栈前提和失败回滚范围。

`--verify-relay` 保留原有四步人工连接对照，同时可读取 iptables／ip6tables 的 filter 表计数及实际引用的 ipset。要求所选 INPUT／FORWARD 首条无条件进入配置的 CrowdSec 链，链内是可识别的无额外条件来源集合 DROP／REJECT，集合类型和地址族匹配；提前 ACCEPT、条件规则、排除项、未知集合类型或缺失计数不能通过。ipset-only 只有已接入同样可识别的 iptables 规则才可使用，集合存在本身不是阻断证据。原有 nftables 路径保留。

新增：

```bash
bash crowdbastion.sh --verify-relay-lifecycle
```

菜单为 `4 → 4 → 3 → 4`。它引导 `2m` 初始封禁、同一原因续为 `4m`、越过原期限后的阻断对照、按唯一原因与 IP 精确删除、恢复，再用新原因创建 `1m` 决策并等待自然到期及恢复。外部测试与决策操作仍由操作者执行；程序只读本机规则并保存私有验收摘要，不发送业务请求、不操作封禁或防火墙，也不访问远端检测中心。

记录明确区分基础连接对照与完整生命周期。旧记录按基础范围展示，取消／失败保存对应退出状态，不改变当前静态健康检查的 traffic pending 结论。

## 计时复审与修复

独立审阅发现并通过失败回归复现两处初版误判：首次决策确认延迟可能延长续封窗口；删除确认过晚可能把自然到期记为删除成功。修正版使用两条保守界限：续封必须在初始命令展示后 120 秒以内完成确认，跨原期限的观测必须在初始提交确认后至少 120 秒。前者早于实际可能到期时间，后者晚于实际可能到期时间；展示与确认之间的操作仍由操作者确认。

精确删除恢复须发生在续封命令展示后 240 秒以内；自然到期须至少等待新短期决策提交确认后 60 秒。提前或过晚确认都不能取得完整通过。取消提示当前活动原因和对应最长等待时间，不自动清除其他决策。

## 边界与交付

向导依赖操作者提供真实外部业务结果，并按展示的原因、来源和时长执行决策；单调时钟约束不能代替操作事实的确认。UDP 必须取得应用响应。计数可能包含同集合中的其他来源；iptables-save 没有 nft rule handle，完全相同规则被重建且计数随后增长时，快照无法可靠识别这种重建。当前读取预算为 15 秒、最多 32 个引用集合及 16×1024×1024 字符，输出收集后检查，不是进程内存硬上限。

当前没有带计数的来源规则、复杂跳转图、Docker bridge 或未核对来源时仍返回未完成，不为了完成向导擅自创建保护规则或关闭检测来源。其他入口、地址族、协议和已有长连接仍需各自验收。

工作在 `/projects/script/CrowdBastion-forwardx-safety` 隔离副本，基于原工作区当时的未提交状态。交付仅同步任务文件，并逐个检查原文件仍匹配初始快照、同步后的文件哈希匹配验证版本；原有其他改动保留。未创建提交或推送，隔离副本保留供核对。
