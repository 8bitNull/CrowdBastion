CPU 亲和性限制为一个核心，与 VPS 的单 CPU 数量相同；CPU 性能、内存压力、其他业务竞争仍不等同。比较 1/2 个 runner 与通知 HTTP 端点 0/500ms 延迟的四种组合，再按逆序重复。每组四批 512 请求、最多 64 并发，批间隔 200ms；一半为正常请求，一半为应被规则拦截的合成路径。每组先要求真实通知到达本地端点，确保通知链已接通。

八组共 **16,384 请求**，预期放行与拦截均符合预期，没有超过 500ms 的响应，最大约 **92.5ms**。每组仍出现 **170–224 条** `Cannot send alert to Plugin channel` 警告。

这说明通知队列警告可以在没有 AppSec 500ms 超时的情况下出现；不能只凭生产日志同时出现这两类记录，就认定通知反压是超时原因。本轮没有复现生产超时，也没有证明增大 runner 或调整超时可以解决它，线上数值未调整。
