## 使用与证据范围

在机器人发送 `/inspect` 调阅告警，点击“执行核验”，随后可以“刷新执行核验”。页面分别查询当前 LAPI 决策和同来源 IP、同时间窗内的 Web 执行记录：

- **已观测到同源 Web 拒绝**：显示实际拒绝原因、观测数量、最近响应状态和服务器生成的请求 ID。
- **尚未观测到**：本次可读日志范围内未匹配；不据此判定漏防。
- **证据日志不可用**：日志或模块无法读取，不能判断执行结果。

官方自动推送仍说明推送时未核验，并引导上述查询。推送可能早于执行决策，不能直接显示所有告警“已拦截”。回执从本次升级后的新请求开始生成，历史请求不会补录。

同 IP、同时间窗证明该来源发生过拒绝，**不能证明原始触发请求或本告警某条决策已经执行**。本期覆盖托管 Web Lua Bouncer 的 ban 4xx/5xx；不覆盖重定向、验证码/挑战或防火墙 DROP。模拟告警只作为独立来源观测的查询入口。

最近告警的生产离线查询成功读取 **33 个日志尾部，读取错误 0**，没有匹配回执，显示“尚未观测到”。部分日志发生尾部截取，因此该结果只覆盖有界抽样，不代表完整流量。

## 实现和保留项

实际 ban 分支写入请求私有标记，log 阶段确认最终拒绝状态与预期一致、主请求且未使用业务 upstream，再输出回执。原因区分 LAPI ban、已有 LAPI 故障拒绝、AppSec 规则拒绝、AppSec 故障拒绝及请求体策略拒绝。业务上游自身的 403 和客户端伪造的 ID/标记不会直接成为回执；1Panel 原 log hook 保留并先执行。

读取器验证日志来源格式和字段，拒绝符号链接；最多 4 个目录、128 个日志、每文件尾部 64 KiB、总 8 MiB，最多 24 小时时间窗；读取当前和 `.1` 轮转日志，报告截取和读取错误。默认 NPM 日志目录，可用机器人配置 `execution_log_dirs` 指定。结构化字段和 TG 核验卡不含 URI/UA/密钥；Nginx error 日志整行仍会自动附加可能含 URI 的请求上下文。

升级保留账号、Token、Chat ID、管理员、配置路径和 Bouncer 策略。目标仍为 `APPSEC_FAILURE_ACTION=passthrough`；没有给此既有安装新增 LAPI 故障拒绝策略。已保留项目目录中并行加入的新安装 LAPI 策略支持。线上机器人以功能增量更新，保留其原有其他操作函数。重启不再发送“已上线”消息。
