# 智能流程循环复审记录

## 已确认并修复

- 首轮：修复正常 Hub 索引导致修改前提永远不完整、远端凭据准备顺序、网站日志与系统日志混淆、远端维护范围越界、既有观察服务故障漏推荐、空网站选择阻塞基础安装、辅助任务无法有限完成、无关变化重现暂缓，以及损坏历史使首页退出。
- 第二轮：暂缓不能绕过部署冲突或未完成变更；有效外部 AppSec 配置参与识别；选中网站日志不再扩大到共享挂载目录。补齐服务启动的修改前提、失败快照保留、容器复用目标和汇总失败传播。
- 第三轮：事务记录损坏或扫描不完整时阻止新修改；自定义镜像按选中容器的实际 Nginx 配置接入，无法读取时明确失败；非法验收时间戳降为历史不可用。
- 第四轮：无名称线索的自定义镜像也能按实际配置被发现；日志模式补来源核对任务；锁内复核覆盖实例外置 Bouncer 配置和登记变化。
- 第五轮：必要恢复清单和 AppSec 监听证据先于可选容器发现采集；在线请求模式同样不能在来源未知时新增网站日志接入；智能流程的网站基础安装只安装系统/SSH 基础，避免旧网站安装后端自动扫描全部实例。Docker 网站接入状态独立核对实际 AppSec 地址、监听与容器登记，不再用真实 IP 核验记录替代。旧 CLI 的网站安装行为保持兼容。
- 第六轮：历史验收摘要与适用性检查受剩余预算约束，配置指纹只计算一次；无预算或超时保留历史未核验。修复后独立终审未再确认 Critical/Important 功能问题。

每个确认的功能问题先补失败复现，再修复和运行相关回归。独立复审只读检查当前工作区，修复不操作真实 VPS、生产防火墙或线上服务。

## 仓库提交前补充复核

再次独立审查确认并修复两项问题：Debian 常见的 Nginx 模块配置链接指向 `/usr/share/nginx/modules-available` 时，原配置指纹会误判不完整并阻止智能修改；宿主机网站的官方请求钩子有效时，原接入状态未核对 Bouncer 实际 AppSec 端点与有效监听，可能将错端口配置标为已接入。

模块配置目录现纳入指纹范围，检查目录链和目标文件的归属、写权限，目标内容变化会使指纹变化，原有外部链接和预算限制仍生效。宿主机与 Docker 共用实际端点核验，缺少有效采集或监听证据时保持未接入。

两项新增回归均先复现原故障，再通过修复；覆盖模块目标内容变化、不安全文件/目录拒绝，以及宿主机错端口拒绝、正确监听接受和监听不可读拒绝。六个智能流程模块共 159 项通过，修复后的独立复审无剩余阻断问题。
