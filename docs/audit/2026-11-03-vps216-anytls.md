## 已实施：关闭两个 Docker 发布端口的公网入口

- 51080 原为 gost 的 `1080/tcp` 公网映射。先独立部署并验收该端口限制，提交后按用户补充再加入 OpenList 5244。
- IPv4/IPv6 INPUT 按 eth0 入接口和目标 TCP 端口 DROP，覆盖 docker-proxy 主机路径；DOCKER-USER 按 eth0、conntrack ORIGINAL 方向及原始目标端口 DROP，覆盖 DNAT 后端口变化的转发路径。
- 每个入口第一条仍跳转 CROWDSEC_CHAIN，两条有限端口限制紧随其后。没有修改默认策略、flush、整表 restore、修改 Compose 或重建业务容器。
- `/usr/local/lib/crowdbastion216-private-gost/policy.py` 当前管理两个端口；`crowdbastion216-private-gost.service` active、enabled，启动顺序在 Docker 和 Bouncer 后。幂等重复应用已验证。该 oneshot 保证开机应用；不承诺管理员重建全部防火墙后的持续自愈，之后应重新运行该服务。
- 两次独立事务均先准备回退脚本和 5 分钟定时器，再应用规则。外部/本机/配置核对后持锁提交，已停止对应定时器。未执行生产回滚演练或宿主机冷启动。

## 未保留：TCP 参数调整

准备阶段确认三份实际 sysctl 文件存在重复网络赋值；`99-sysctl.conf` 是 `/etc/sysctl.conf` 的链接。曾应用将 64 项实际运行值集中到单文件的候选配置，保留 BBR/fq 和 16MiB 缓冲上限，仅调整 SYN/SYN-ACK/orphan 重试及 TCP 全局内存阈值。文件摘要、64 项运行值、重复赋值消除、systemd 开机配置解析均通过。

后续业务核查中，远端 curl 进程超时，LAPI 决策请求也连续出现约 10 秒超时。无法将其确认与参数变更无关，因此没有提交调优事务，主动执行精确回退。回退输出 `rolled_back: true, errors: []`；再次核对原文件摘要、候选新文件不存在及四项运行参数恢复均通过，并停止网络回退定时器。

当前仍是原先的网络配置：tcp_syn_retries=3、tcp_synack_retries=2、tcp_orphan_retries=1、tcp_mem=122112/244224/488448。不能声称网络调优已完成。末次 LAPI 在回退后恢复响应，也不足以凭时序确定参数就是超时根因。公网 HTTPS 首页通过本地独立 curl 返回 200。

远端 `/var/backups/crowdbastion/anytls-20261103/` 保存原配置、候选与 immutable manifest；该事务已回退、未提交。原 stage 额外 iptables-save 曾超时，不能将整个初始阶段标为通过。

## 存储与 AnyTLS 检测仍待查

此前多次 vmstat 采样观察到 I/O wait 98%–100%、约 3–9 个 blocked 进程；XFS 写回线程及读取进程出现 D 状态。内核日志还保留 journald watchdog、启动超时及 120/241 秒阻塞记录，这些是较早 uptime 的历史记录，不能说全是本轮新错误。之后存在多段 0% I/O wait 的恢复窗口，也不能因此认定已修复。

两次临时 WBT 置零测试均有退出恢复保护；第二次没有改善，末次原值为 2000，未持久化磁盘参数更改。根因尚不能归结为 WBT、宿主机磁盘或某个内核 bug；未切换块调度器、重启、升级内核或清理日志。

V2bX 末 3000 条 journal cat 样本有 22 条认证失败相关文本、2953 条 TLS handshake 相关文本。仓库解析器支持 sing AnyTLS 的精确认证失败格式；内存解析验证先遇缺依赖，补齐后 journal JSON 查询仍超时，尚无有效的现场解析统计。未安装新的检测/自动封禁组件。固定中转是共享来源，不应将普通 TLS 错误直接用于封禁整个中转。
