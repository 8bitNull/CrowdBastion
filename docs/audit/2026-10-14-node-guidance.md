# 节点用途与检查引导验证（2026-10-14）

本轮落实已确认的第一轮体验改进：节点用途引导、按用途检查、检查后的下一步入口、取消菜单返回时的重复回车。

## 改动与行为

- 首次终端启动询问网站、本地中转、远端执行、V2bX 落地用途，支持兼容组合；主菜单 `7` 重设、`8` 检查。原有 `1–6` 和 CLI 参数保留。
- 标准库 Python helper 验证并原子保存用途；读取不创建文件。取消／EOF 不保存，冲突组合和不安全文件被拒绝。
- 中转检查系统／SSH 来源读取与解析，远端检查托管 Bouncer 和本机规则，落地可独立诊断。已部署的网站配置仍检查，包含自定义采集目录。
- 远端与远端＋落地模式不查询本地 LAPI 或要求本地核心；已有网站组件只检查配置、监听及运行配置，中心处理指标保持未验证。
- 远端网站检查显式处理 Docker 枚举、配置、挂载和已登记容器停机错误，支持旧版名称／完整 ID／短 ID 接入记录，排除无关容器。
- 检查结果保留异常 `1` 优先于尚未验证 `2`。实际业务阻断没有流量证据时不宣称通过；安装、修复和验证只在明确选择后执行。
- 真实 PTY 重放首次选择、中转返回、V2bX 多层返回及无效输入；返回菜单不再暂停。检查后的安装入口保留锁，叶子结果暂停一次。

## 验证结果

- 最终完整 unittest：**769 项，748 通过、21 跳过、0 失败**。跳过项依赖可选外部实验／官方组件，不代表已完成目标 VPS 的生产验收。
- 用途与引导专项 **32 项通过**，V2bX 诊断 **28 项通过**；覆盖真实终端导航、角色组合、持久化安全、无本地核心、远端隔离、故障优先级和 Docker 兼容性。
- Bash 语法、Python AST 解析、ShellCheck（沿用仓库既定排除项）、更新文档的文件链接及 `git diff --check` 通过。
- 独立审查发现并修正远端隐式本地核心检查、活动采集目录识别和 Docker 读取失败被跳过的问题；最终无剩余 Critical／Important 问题。旧 ID-only Docker 接入记录的兼容性问题也已增加回归并修复。
- 全量命令使用已有虚拟环境，将其 site-packages 加入 `PYTHONPATH`，使旧诊断测试中显式调用的系统 Python 能读取 PyYAML；未修改系统 Python 或安装主机软件包。

## 范围

测试使用临时配置、受控命令边界及本机 PTY，没有部署用户 VPS、重启生产服务或创建测试封禁。测试通过不代表目标节点实际流量阻断已验收。V2bX 配置生成、安装进度和自更新不属于本轮。
