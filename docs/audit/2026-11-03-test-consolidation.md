范围由用户确认：测试分层、公共夹具、逐项耗时统计。本轮只修改测试基础设施和文档，没有改生产逻辑、SSH 登录 VPS、提交或部署。

## 已实现

- 从 `tests/test_workflows.py` 抽离 8 个公共辅助方法到 `tests/workflow_fixture.py`，保持辅助方法源码不变；每项仍创建独立临时树。原测试类继续使用 mixin，AuditSafety/HubMaintenance 改为 mixin + TestCase，删除手动屏蔽继承测试的循环。其余夹具消费者直接引用 mixin；3 个测试内的旧辅助调用保持兼容。
- `tests/run_tests.py` 默认 full；显式 quick 309 项、integration 32 项、archive 22 项。full 包含所有发现项和未分类的新模块。模块可单独选择；未知模块、清单重复/拼写错误、空交集或导入错误不能返回成功。
- `--timings` 保存逐项耗时、状态、跳过原因及统计，保留 unittest 失败、错误、子测试和预期失败语义；`--require-no-skips` 让缺条件的专项无法以“跳过但成功”被接受。
- 用例没有因数量、名称或耗时相似而删除；没有共享可变临时目录或引入并行执行。

原 1655 个测试 ID 和测试方法源码 SHA256 全部保留，无重复发现；8 个辅助方法源码逐一相等。新增入口/夹具约束自测 9 项，因此完整发现为 1664 项。

耗时是本机观察值，部分运行短时重叠，不是受控性能对比；本轮减少的是日常需要运行的范围，未宣称完整套件提速。逐项耗时含用例准备和清理，不含模块/类夹具和导入成本。

完整基线逐项累积较慢的模块为 Workflows 127.90 秒、Nginx reload 32.43 秒、Hub maintenance 29.66 秒、script review fixes 29.31 秒。慢项包括 reload 失败恢复约 20.58 秒、多个真实超时/重启场景约 10 秒。这些用例承担独立的失败路径验证，不能仅为提速删除；后续应先区分进程启动、夹具准备和业务等待，再决定可否注入时钟或合并等价输入。

独立复审 `/root/test_consolidation_review` 无 Critical、Important、Minor 发现。复审另行验证类/模块 setup、teardown 错误及混合 skip/error 子测试，退出码和报告状态正确；复审没有代替主任务的完整测试。新增入口按 RED→GREEN 验证，初次失败因入口尚未实现。修改 Python 的语法、仅本轮新增行的空白检查通过。
