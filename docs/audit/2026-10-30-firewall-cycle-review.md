# 防火墙维护流程循环复审与修复

接续[四台 VPS 验收回流加固](2026-10-30-four-vps-script-hardening.md)，复审新增检查、启动配置、迁移、流量验收和回退，以及管理入口和 cron Hub 维护的并发边界。保留工作区原有改动和历史证据；本轮没有连接或修改 VPS、发送 Telegram 消息或创建提交。

## 第一轮：封禁覆盖和回退

| 确认的问题 | 修复与验证 |
| --- | --- |
| 内核成员按集合名称汇总，未要求被有效规则引用 | iptables 只计入双栈无条件 DROP 路径实际引用的集合；原生 nftables 按配置表、地址族和 input／forward 各路径分别核对。未引用的同名集合和其他表不能补足缺失成员 |
| CrowdSec 链前部 ACCEPT／RETURN 仍可能被后方 DROP 误判为通过 | 整条托管链必须由可识别的来源集合 DROP 组成；负匹配、协议条件、提前放行或 RETURN 均不报覆盖通过。枚举命令失败保留“尚未验证”，不当作已确认路径缺失 |
| 业务规则比较没有区分表，可能错误过滤 nat 内同名链 | 逐表比较规则、链及策略，仅排除 filter 表内本事务负责的 CrowdSec 新增内容；计数器变化不造成误报 |
| 同内容符号链接能通过字节漂移检查；回退丢失原权限 | 路径类型变化拒绝覆盖；备份 mode／uid／gid，回退时恢复原权限及归属 |
| 准备阶段快照失败可能留下不能正常回退的半成品状态 | 完整准备后写入 prepared 标记；准备中断且没有系统变更标记时记录终止状态并保留备份，释放后续维护阻断 |

## 第二轮：验收进程、中断和并发

| 确认的问题 | 修复与验证 |
| --- | --- |
| CLI 被终止后验收子进程可能仍操作规则；回退没有先清理验收资源 | 验收改为独立 systemd 服务，有最长运行时限；启动前记录所有权。verify 的 finally、回退和独立清理定时器先停止验收服务，使用单独的 flow.lock 串行清理后才继续 |
| 清理中某一步失败会跳过后续资源；清理失败可能以零退出结束 | 清理独立尝试服务、决策、规则、命名空间及接口；失败保留活动标记，验收以失败结束，提交和回退不会在未确认清理时撤销保护 |
| 测试放行追加在 DOCKER-USER 的 RETURN 后可能无法生效 | 临时规则插入已核验 CrowdSec 首条跳转之后，仍受封禁约束；仅匹配测试接口、地址、协议与端口，清理后恢复原业务顺序 |
| 续封等待从 cscli 调用前计时，慢命令可能让检查提前 | 从初次决策创建完成后计时，越过原期限再检查；自然到期同样从创建完成后计算。慢命令模拟验证不会提前检查 |
| 验收可以在回退窗口过晚时启动 | 预留完整验收、清理和提交窗口；不足时不创建验收服务，保持回退 |
| 未提交事务期间其他管理修改会导致配置漂移；cron Hub 入口绕过普通锁包装 | 普通修改入口、维护菜单的启动修复和 Hub 独立入口均阻断；只读检查、验收、提交及回退仍可用，终态后解除阻断 |

## 第三轮：兼容和诊断

- 复用四台现场无注释的 `[Unit] / After=docker.service` 旧版 drop-in，不因缺少新版注释而拒绝或改写；新增文件使用原子写入。
- 已发现的开机任务／恢复服务问题不会被后续探测失败覆盖成“尚未验证”；不可读取的部分仍说明检查未完成。
- 原生 nftables 引用解析通过仓库归档的真实 VPS 规则结构校验，覆盖实际 CAPI／crowdsec 来源集合及具名 counter；迁移预检拒绝无法确认双栈原生入口或非默认 DROP 策略。
- 复核事务副本所需模块、独立服务命令、锁与状态标记顺序、日志脱敏和失败传播；没有扩大迁移到自定义策略或远端 LAPI 的支持范围。

## 验证与范围

结果、运行命令和完整日志见同名证据目录的 `results.json`、`focused-regression.txt`、`full-regression.txt` 与 `static-checks.txt`。最终源码和证据的摘要位于 `SHA256SUMS`。

本轮新增 24 项复审回归，针对性检查 67 项全部通过；阶段性集成回归 102 项通过。另以全部系统命令模拟的规则顺序模型执行真实 setup 函数，验证两地址族临时规则位于 CrowdSec 跳转之后、Docker RETURN 之前，见 `flow-rule-order-model.json`。最终全仓 **1236 项：1147 通过、89 跳过、0 失败／错误**，耗时 401.947 秒，退出 0。最终代码在这次全仓启动前已完成，后续只整理文档及证据。较早启动的一次完整回归因收尾代码变化主动中断，退出 130，不作为完整通过证据；最终完整回归从头运行。

静态检查：137 个产品及测试 Python 文件 AST、主入口及 16 个 Bash 模块语法、ShellCheck warning/error（沿用 SC2317、SC2329、SC2120、SC2119 排除项）、暂存及未暂存差异格式检查均通过。

运行命令：

```bash
PYTHONPATH="$PWD/lib:$PWD/.venv/lib/python3.11/site-packages" \
.venv/bin/python -m unittest discover -s tests -v

PYTHONPATH="$PWD/lib:$PWD/tests:$PWD/.venv/lib/python3.11/site-packages" \
.venv/bin/python -m unittest test_firewall_runtime test_firewall_review -v
```

所有系统变更测试使用临时文件和模拟 systemd／LAPI／防火墙命令；真实 VPS 归档仅用于解析，不是本轮现场部署测试。当前工作环境缺少 ip、nft、iptables，未执行真实宿主机迁移或网络命名空间流量实验。公网实际业务阻断仍需独立验收；定时器实际回退也可能受事务锁、系统调用超时和系统故障影响。

历史报告中的源码摘要表示当时版本，本轮不改写旧摘要；当前源码以本轮摘要清单为准。
