# 本地 Bouncer 安装失败：后续定位

本轮继续调查上一阶段 Debian 13 / Ubuntu 22.04 / Ubuntu 24.04 的官方 nft Bouncer 包 `postinst` 返回 1。历史矩阵保留，不覆盖原失败。

采用 systematic-debugging：先采证，再确认假设，最后才修改生产代码。对照为同一官方已校验 Debian 13 镜像、1 GiB 请求内存、1 vCPU、8 GiB 独立 snapshot 磁盘：直接安装本地核心与远程生命周期完成后安装本地核心。后者仅清理实验室拥有的保留文件以构造本地案例；产品仍拒绝直接迁移。

两个客机均有界 1500 秒；安装命令有界 900 秒。采集安装退出码、脱敏命令输出、实际软件包版本、服务退出状态、unit journal 和 Bouncer 日志。日志不打印配置或密钥；宿主不安装包、不改服务/防火墙、不发布端口、不共享目录、不发送外部通知。临时采证脚本位于 `/tmp/crowdsec-core-diagnostic`，不是产品接口。

已确认退出点：官方发布的 `crowdsec-firewall-bouncer-nftables 0.0.36` 辅助脚本启用 `set -eu`，在检测到伪终端后使用 `tput` 初始化颜色。实际客机的 `TERM=vt220`、`NO_COLOR` 未设置；`tput sgr0` 成功，`tput setaf 1` 因终端不支持颜色失败，赋值命令返回非零导致脚本退出。客机中加载实际包辅助脚本的追踪停在 `FG_RED=`，退出 1。包处于 half-configured，本地 Bouncer 尚未启动，核心已 active。

直接安装和远程流程之后安装都复现同一现象，因此此失败不依赖远程配置残留。只把服务状态当作启动失败会误判，根因发生在包脚本颜色初始化。

最小修复：`install_packages` 的 Debian/Ubuntu apt 安装调用临时设置 `NO_COLOR=1`。不更改终端类型、不修改 upstream 包文件、不掩盖 apt 错误，不修改调用者环境。针对 apt 给包脚本提供 PTY、单色终端不支持 `setaf` 的回归测试：修改前退出 1，修改后完成配置；apt 返回 29 的独立失败仍返回 29。真实客机完成了单变量重试及修复后干净首次/重复安装、重启、决策增删。

实际发布包从官方 apt 索引下载并校验，SHA256：`fb3f38d222793cd031dac7e2b33076033a05c5bb476f323129d431cdc8b69b78`。只在宿主解包读取脚本，没有在宿主安装或执行其包配置流程。

## 最终回归

终端回归用例经历先失败、再通过；独立审查验证了实际官方包辅助脚本的 PTY 行为、环境作用域、apt 失败码传递和严格验收条件。最终全仓 unittest 共 522 项，505 项通过、17 项跳过，无失败；ShellCheck、Bash 语法和差异检查通过。

首次与 QEMU 客机并行的全仓运行中，0.2 秒短窗口回显负载测试报告成功请求数为 0；该测试单独复跑通过，所有客机结束后完整回归通过。保留首次回归失败记录，没有修改负载程序来掩盖失败。

最终独立复核确认三个系统共 15 个案例的验收条件成立，8 份脱敏日志校验值及源码与 seed 的对应关系一致，报告与 JSON 一致，无尚未处理的重要问题。
