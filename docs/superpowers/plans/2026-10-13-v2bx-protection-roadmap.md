# V2bX 混合入口防护阶段计划

> 执行方式：后续使用 executing-plans 分阶段实施；本文件是阶段路线和验收约定。第一阶段诊断完成后，再根据实际配置、日志样本和网络路径制定各内核的详细实现计划。

**Goal:** 为同时运行 xray、sing、hysteria2，且中转与用户直连并存的 V2bX 落地建立可验证的检测与封禁能力。

**Architecture:** 分内核采集日志，按实际协议和可靠来源识别异常，复用 CrowdSec 与官方 Bouncer。直连用户在落地执行封禁；经中转的用户根据网络可见源地址选择执行节点。不能恢复用户来源的事件仅告警。

**Tech Stack:** 项目已有 Bash、Python 3/PyYAML、CrowdSec、Firewall Bouncer，以及部署中的 V2bX。

**Spec:** 本次会话认可的混合入口方案：三个内核及其部署协议均纳入评估；可信来源识别、分路径执行、分协议限速与上游带宽防护。

## 全局约束

- 实现仅涉及本地诊断和离线验证，不改变生产配置、服务、决策或防火墙。
- 三个内核均覆盖诊断；规则支持按实际版本、协议与可用日志逐项验收，不能宣称一次支持全部协议。
- 不输出面板 API Key、用户 UUID/密码、证书私钥、完整配置或未脱敏的业务访问目标。
- 读取配置只提取允许字段；日志输出只展示经过脱敏的必要事件，不用宽泛正则脱敏原文后直接展示。
- 区分配置声明、本机证据和端到端验证；配置存在不等于保护生效。
- PROXY protocol 等真实 IP 元数据仅接受已确认支持的协议、可信中转和受限入口；不能据此推断内核数据包来源。
- 中转 IP 不因汇聚业务错误自动生成封禁决策；不自动加入覆盖所有检测的全局白名单。
- 用户限速、设备限制和账号处置由 V2bX/面板承担，IP 封禁不代替账号管理。
- 不提供本机带宽清洗承诺；不使用所有协议共用的默认限速阈值。

## 第一阶段：只读诊断与证据清单

**拟议文件职责：**
- 新建 `lib/crowdsec_v2bx.py`：允许字段提取、内核/节点/日志识别、证据状态和脱敏报告。
- 新建 `lib/v2bx.sh`：薄层诊断调用，沿用现有路径与依赖约定。
- 修改 `install-crowdsec-1panel.sh`：增加 `--diagnose-v2bx`、帮助及诊断菜单入口，作为只读操作分发。
- 新建 `tests/test_v2bx_diagnosis.py`：配置与来源判断、秘密不输出、异常处理和只读行为回归。
- 新建 `docs/v2bx-guide.md`：诊断说明、路径矩阵、支持状态与限制。

- [x] 实现版本候选、启动方式、配置来源、启用内核与节点核查；兼容性不明确时报告未验证。
- [x] 提取协议、监听 IP、日志配置引用和真实 IP 配置声明；面板端口/传输缺口明确标记，不从公网扫描推断服务。
- [x] 输出本地 socket 与服务 PID 的关联证据，节点映射保持未验证；复用既有 endpoint 和 Bouncer 审查，不复制 NAT 解析器。
- [x] 检查日志可读性与 CrowdSec 采集配置，区分失败候选和普通错误，均不宣称专用检测可用。
- [x] 支持按节点声明直连/中转/混合路径，输出条件性封禁位置；日志 IP、数据包 IP 与信任状态需目标 VPS 端到端核验。
- [x] 用正常/错误事件、缺失配置、失败查询、未知协议、其他进程端口、IPv6、FIFO 和带凭据样本验证诊断输出。
- [x] 运行定向单元测试、Bash/Python 语法检查及 diff 检查；完整回归和 ShellCheck 结果记入验证文档。

**验收：** 报告能回答每个节点“谁监听、哪里有日志、来源是否可信、在哪执行封禁、哪些尚未验证”；不重启服务、不写入采集或白名单、不修改防火墙，并且不泄露秘密。

**本阶段完成后需要的部署证据：** V2bX 版本；三个内核实际配置的允许字段；各协议脱敏的成功与明确失败日志；每条入口的中转工具和源地址处理方式。日志中没有失败事件的协议明确记为暂不可接入，不虚构样本格式。

## 第二阶段：逐内核日志检测，先观察

- [ ] 根据第一阶段证据，为 xray、sing、hysteria2 分别制定解析器和场景计划；事件提取时间、可靠来源 IP、内核、协议、节点及失败类型。
- [ ] 只纳入明确认证失败和明确无效请求；网络超时、客户端重连、目标连接失败、设备超限不直接触发封禁。
- [ ] 避免重复采集，限制日志容量并配置轮转；尽量使用现有错误日志，不默认开启全量 debug/access。
- [ ] 使用实际脱敏样本进行离线解析和官方引擎验证，再在目标部署观察告警；初始场景不产生自动封禁。
- [ ] 验收正例命中、普通网络错误不命中、IPv4/IPv6 提取、未知日志拒绝归因，以及中转地址不会被当成攻击用户。

**验收：** 每个已支持协议都具有可复现样本和误报核查记录；没有可靠失败日志的协议保持告警/诊断能力，不宣称完成专用检测。缺日志时单独评估是否需要上游 V2bX 修改。

## 第三阶段：正确位置执行封禁

- [ ] 用隔离测试来源核验直连、中转保源、中转代理三类实际路径；覆盖已部署 TCP/UDP、IPv4/IPv6。
- [ ] 复用中心 LAPI 与远程 Bouncer；用户来源丢失时不能向落地防火墙发送中转 IP 作为用户封禁替代。
- [ ] 中转业务入口若与 SSH、直连共用防火墙策略，先评估决策范围，避免一个业务事件扩展成所有服务封禁。
- [ ] 从确认无误报的场景启用短时封禁，并提供撤销、停用和恢复流程。
- [ ] 验证攻击测试来源被阻断、健康来源仍可访问、中转连接正常、解封后恢复；分别说明新连接和既有连接效果。

**验收：** 封禁有实际数据包/连接证据，且不会因中转汇聚误封整批用户；未通过的路径保持仅观察。

## 第四阶段：入口限速与运行维护

- [ ] 根据正常峰值与机器容量制定每个入口的 TCP/UDP 限速计划；直连与中转汇聚采用不同预算，不能未经测量给定统一阈值。
- [ ] 核实 V2bX 各内核和协议的用户限速、设备限制实际效果；不把仅存在的 `ConnLimit` 字段视为已生效。
- [ ] 评估是否拆分直连/中转监听端口或 IP；支持条件与迁移影响确认后再实施。
- [ ] 网络限速配置独立于 CrowdSec 日志场景，具备预览、备份、撤销与重启持久性验收。
- [ ] 监控 CPU、内存、日志增长、丢包、连接数、解析率和误封；记录带宽攻击需要的上游服务与联系方式。

**验收：** 正常业务峰值可用，异常负载下资源有改善，回滚可恢复；不将本机资源改善解释为带宽型 DDoS 清洗。

## 执行顺序与完成条件

先实施第一阶段。依据其报告选择第二阶段中有可靠证据的协议，不让缺失日志的协议阻塞其他协议。第三阶段以来源可信与路径验证通过为前提；第四阶段以正常负载基线为前提。每阶段单独交付、测试和说明支持范围。

## 第一阶段实施记录

已增加 `--diagnose-v2bx` 和菜单 `4 → 12`，以及 JSON helper、使用指南与 25 项专项回归。独立审查指出的 scoped IPv6 任意字符串输出、未解析 Include 的错误默认地址、sing Disable 字段、Hysteria2 不支持的日志目的地与 CrowdSec FIFO 配置阻塞均增加回归并修复。

当前工作环境未发现实际 V2bX 服务；验证使用本地隔离文件/命令样本，未修改生产防火墙、服务、采集或决策。第二阶段仍需实际 VPS 的版本、入口来源与各协议脱敏失败事件；历史 journal 版本、采集引用和本地封禁规则引用都不能替代真实业务验收。

## 第二阶段离线部分实施记录

已实现 `--v2bx-log-check`（菜单 `4 → 13`）、固定字段日志投影、显式时间依据、中转来源排除，以及未安装的非修复规则样板。按 V2bX 替换依赖源码构造样本，官方 CrowdSec 1.8.1 临时引擎读取 13 条事件并形成 5 条观察告警、0 个决策。Xray Trojan 的两类拒绝记录可能进入 fallback，保持中性；Hysteria2 无可用认证失败日志，只记录连接。详见[离线计划](2026-10-13-v2bx-log-observation.md)和[验收记录](../../audit/2026-10-13-v2bx-observation.md)。

上方第二阶段验收项仍未勾选，因为需要目标 VPS 的真实版本、日志、误报和生产采集证据；离线样本不能替代这些证据。第三、第四阶段亦未实施。
