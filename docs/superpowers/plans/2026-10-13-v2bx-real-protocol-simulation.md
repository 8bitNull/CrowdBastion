# V2bX 真实三内核协议模拟验收计划

> 按用户授权在当前分支顺序执行，不修改生产配置，不自动提交；复用现有隔离 QEMU。临时验收程序为实验代码，归档后供复查。

**Goal:** 运行官方 V2bX，验证三个内核实际声明的协议组合及真实日志，区分业务成功、认证拒绝和日志检测缺口。

**Architecture:** 无外网 NIC 的 QEMU 内建立客户端、中转、落地命名空间。受控 UniProxy API 返回临时节点和账号，V2bX 同时运行三内核。真实 sing-box 客户端通过 SOCKS 请求随机令牌本地 HTTP 目标，错误凭据后再测健康恢复；日志仅输出固定投影字段。

**Tech Stack:** 官方 V2bX v0.4.0（3deccaa）、sing-box 1.12.0 客户端、Python 3、QEMU TCG、既有隔离网络 helper。

**Spec:** 本会话用户认可的真实程序模拟验收：实际协议流量、真实产生的日志、受控面板与账号、正常和失败对照，不能用构造日志替代。

## 范围与条件

- v0.4.0 内嵌依赖与之前分析的仓库 HEAD 不同，分别记录，不将两版兼容性混为一谈。
- 基础组合：xray VMess/VLESS/Shadowsocks/Trojan，sing 上述四种加 TUIC/AnyTLS/Hysteria/Hysteria2，以及 hysteria2 core，共 13 组合。
- 基础传输分别使用 TCP、TLS 或 QUIC，Shadowsocks 为一个已明确的 AEAD cipher；不声称全部传输、密码套件、REALITY/XHTTP/mux/UDP 代理载荷均通过。
- 先保证直连真实握手，再扩展代理中转和典型网络错误；IPv6和其他传输单列待验证，不能用前轮回显结果替代。
- TLS 使用本机生成的测试证书和固定测试域名，优先用证书文件验证；不操作公共 DNS/ACME。
- 每个客户端请求校验随机令牌，不能把监听、进程存活或 SOCKS 建连当成功。错误凭据不应取得目标响应，健康恢复必须成功。
- 生效日志窗口按测试时间/阶段隔离，来源只取实际日志字段；原始凭据/目标/日志只留临时受控客机，归档只含白名单字段。
