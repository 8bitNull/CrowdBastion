# Existing Deployment Implementation Plan

> **For agentic workers:** Use executing-plans to implement the authorized tasks in this session. 用户已确认实施，完成实现和独立复审，无需再次选择执行方式。

**Goal:** 将真实 VPS 发现整合为统一的只读证据检查和可确认的已有部署修复流程。

**Architecture:** 共用 Python 防火墙证据算法，Bash 保留导航和现有事务；健康摘要通过类型事件输出结果。

**Tech Stack:** Bash、Python 3、既有 PyYAML、unittest。

**Spec:** `docs/superpowers/specs/2026-11-01-existing-deployment-design.md`

## Global Constraints

- 不新增依赖；不重启 Docker/VPS；不自动切换后端或安装。
- 所有写操作沿用维护锁、确认及私有备份；读取失败不猜测健康；凭据不写入报告。
- 保留已有工作区补丁与证据，不自动提交推送。

## Tasks

- [x] 1. 提取通用决策读取、适用决策选择和引用集合覆盖算法；新增独立回归验证空闲、遗漏、过期、过滤未知、读取失败及凭据隐藏。
- [x] 2. 接入 runtime、relay、迁移验收及健康摘要，使用同一规则解析，保持远端、非 iptables 和旧 CLI 的边界。
- [x] 3. 增加已部署检查修复入口：检查、范围、确认、备份、明确 root 开机任务处理、现有配置事务、有限期同步等待与结果记录；补充取消/EOF、冲突、不改 Docker、回滚测试。
- [x] 4. 更新文档，独立复审，专项及全量回归；同步授权 VPS 源码，健康时只读复查，保存脱敏证据。

## Review Focus

- 禁止调用决策 stream GET 或跟随重定向；不泄漏认证信息。
- 过滤与决策变化不能造成假遗漏；未知不吞掉确定的路径故障。
- 只能计算实际引用的内核集合；不存在集合及错误地址族不能通过。
- 旧开机任务逐项确认，其他任务、快照和来源权限保持。
- 有效保护配置不因社区同步延迟无期限等待；取消和 EOF 不改部署。
