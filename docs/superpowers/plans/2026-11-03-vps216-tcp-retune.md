# VPS216 按内核原理重新配置 TCP

用户已授权查询资料后重新配置，直接执行本轮方案；操作仅涉及远端配置及本轮归档，不修改已有产品代码、不提交推送。

## 依据和选择

资料已实际下载：Linux v6.18 `Documentation/networking/ip-sysctl.rst`、`net/ipv4/tcp.c`、`net/ipv4/tcp_ipv4.c`，man7 `tc-fq(8)`，AnyTLS 官方 protocol.md 和 sing-box AnyTLS 入站文档。版本化内核资料优先于 latest。现场 `unshare -n sysctl` 在临时独立网络命名空间读取本机内核默认值，进程退出即销毁，未修改主机参数。

AnyTLS 是 TLS/TCP 会话复用，UDP 使用 UDP-over-TCP；不能按原生 QUIC 代理套用 UDP 调优。BBR/fq 已生效，UDP 缓冲错误和 TCP 内存压力无新增，现有 TCP 缓冲 16MiB 上限不需要凭空增大。上轮将 tcp_mem 一并缩小缺乏足够因果证据，本轮不改变全局 tcp_mem、UDP 缓冲、队列上限或应用协议配置。

选择稳健基线，恢复本机新网络命名空间实测的默认行为：syn_retries=6、synack_retries=5、orphan_retries=0（实际内核初始化值，文档所述有效重试语义需与源码区分）、fin_timeout=60、autocorking=1、no_metrics_save=0、tw_reuse=2。相较激进缩减超时/全局内存或扩大队列，这些调整有可核查的内核依据，目标是连接容错及正确行为，不能直接承诺吞吐提高。

保留当前其余网络运行值，将三份实际配置中的 active net.* 值集中到单一文件，保持别名和非网络设置。更改这七项以外的参数需要新证据。
