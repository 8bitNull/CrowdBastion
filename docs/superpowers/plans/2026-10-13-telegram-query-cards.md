# Telegram 查询卡片优化计划

目标：落实已确认的封禁决策与站点体检手机卡片；取证执行状态保持证据边界。

架构：在现有标准库机器人中增加只读 JSON 查询和分页渲染，安装器仍只部署同一机器人文件。翻页编辑原消息；查询重新采样，不缓存已过期决策。站点首版仅查看容器和管理配置记录，不主动发送 HTTP 请求。

- [x] 决策：先添加分组、重复决策、Range、分页、失败、HTML 长度回归；运行确认失败；实现 `module_decisions(page=0, target=None)` 返回文本和 inline_keyboard。官方 `-l 50` 限制告警数量，默认不包含 CAPI；完整保留分组内决策，详情分页展示。
- [x] 站点：先添加运行/停止/health/无 Docker/空列表/配置哈希变化回归；运行确认失败；实现 `module_sites(page=0)`，仅查询 `docker ps -a` 及所选容器的 State。管理记录按 CrowdSec 配置目录读取，不展示密钥或完整 inspect。
- [x] 回调：测试管理员授权、无效分页、翻页编辑；主菜单切换至卡片入口，保留取证和 IP 解封操作。
- [x] 集成：使用临时官方 1.8.1 引擎确认决策 JSON 格式，添加实际决策查询验收；不调用 TG、宿主 systemd 或防火墙。
