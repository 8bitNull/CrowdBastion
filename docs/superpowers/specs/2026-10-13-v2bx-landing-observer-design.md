# V2bX 落地常驻观察设计

用户已授权按“常驻仅观察、来源核验后再接入防护”的顺序继续。第一阶段只负责本地采集服务，不安装 CrowdSec acquisition、场景或 profiles，不创建决策和限速规则。

复用现有 Observer，每个独立日志源一个 SQLite 数据库；JSON 配置最多 16 个源，支持三个 core、固定时区偏移、共享中转 CIDR、unit、每源容量。相同文件／inode 不得重复采集，混合 core 共用一个日志文件暂不支持；不修改 V2bX 日志配置、不建立 journal 导出服务。

systemd 服务从私有固定安装目录运行已复制的 helper，而非依赖仓库路径。每 0.5–60 秒轮询，原子写入脱敏指标、心跳和来源状态；SIGTERM 关闭所有数据库，重启复用游标。容量满或关键输入失败必须退出并留下固定错误码，不无限重启。保留既有轮转、copytruncate 与迟写风险。

提供安装、只读状态和停用 CLI。首次安装只创建专用文件，拒绝覆盖已有安装及同名外部 unit；启动失败撤销新安装。停用只停止并禁用本工具 unit，保留配置与数据库。安装／停用需 root；状态不能靠 active 宣称业务防护通过。固定目录拒绝符号链接、不可信所有者和可写权限。配置不作为 shell 代码执行；输出不带原始日志和异常文本。

默认每源 100000 事件，到达容量硬停止，不自动删事件；systemd 内存上限 256 MiB、CPUQuota 20%、UMask 0077、只允许状态目录写入。限制是资源配置而非公网负载验收。真实 VPS 部署需明确日志路径、中转出口及受控客户端证据。

测试覆盖真实文件追加、退出／重启不重采、三内核源、多源冲突、中转标记、容量停止、缺失源、配置严格验证、安装失败撤销、只读状态与停用保留文件；系统服务生命周期用隔离 systemctl fixture，不代表真实 systemd 验收。
