# 节点用途与检查引导

用户已确认第一轮体验优化：节点用途引导、按用途检查、检查后的下一步入口，以及取消多余回车。本文落实这四项；V2bX 配置生成、安装进度和脚本自更新属于后续工作。

## 节点用途

- 支持 `web`（网站）、`relay`（本地系统/SSH 检测中转）、`remote`（只执行远端中心决策）和 `node`（V2bX 落地），可以组合选择。
- `remote` 与 `web` / `relay` 不能同时选择，避免把远端 Bouncer-only 节点引导到本地核心安装；`remote node` 合法。
- 配置持久化到 `/var/lib/crowdbastion/node-roles.json`，使用 Python 3 标准库读取与原子写入；不依赖 PyYAML，不执行配置内容，不保存凭据。
- 首次交互终端运行、且没有已保存用途时显示引导。已有组件只用于提示候选，不自动确定用途。输入 `0` 或 EOF 取消，不写文件、不安装组件。
- 命令行状态检查读取已保存用途，未选择时保留现有检查行为，不增加交互。损坏或不安全的配置不能静默选择其他用途。
- 主菜单保留 1–6 与现有命令行参数，增加用途设置与推荐检查入口。首页显示用途和按用途推荐的入口，不再固定宣称首次安装应走网站模式。

## 按用途检查

- 网站用途继续使用现有 Web/AppSec、服务、LAPI、配置及业务证据检查。
- 本地中转重点检查核心、LAPI、系统/SSH 日志读取与解析、Bouncer 规则引用。没有网站配置时 AppSec 网站接入显示“不适用”，不运行 HTTP/Docker 网站检查。
- 落地用途执行 V2bX 诊断；已有本地核心同时检查基础系统防护。未部署核心时不阻止独立 V2bX 诊断，也不能宣称 SSH 防护已安装。
- 远端用途不要求本地 CrowdSec，不执行本地 LAPI、SSH 采集或网站检查。检查托管远端 Bouncer 状态及本地防火墙规则引用，明确检测由中心负责。
- 组合用途覆盖各自相关项。若用户未选网站但存在本工具的网站/AppSec 配置，明确提示并核查已部署组件，不能将已部署组件故障隐藏为“不适用”。
- 系统/SSH 日志按来源显示 reads / parsed；无法归类或无新日志标为尚未验证。读取日志和解析成功不能当作攻击检测通过。
- 保持正常、异常、尚未验证、不适用的区别。退出码 `1` 优先于 `2`，实际业务阻断未验证时仍返回 `2`；没有实际流量证据不得改为全部保护通过。
- `--status` 和所有只读检查不创建封禁、修改服务、账号、防火墙、采集、profile 或用途配置。

## 下一步与导航

- 检查结果说明本次结论和有依据的下一步；CLI 只打印建议，不等待输入。
- 交互检查后可以直接进入用途匹配的安装、专项检查或修复入口。选择下一步才执行；需要修改的操作仍保留锁、既有确认、备份及回滚。
- 缺少核心时按用途引导安装：网站使用 web，纯中转/落地基础系统防护使用 relay，远端使用远端配置入口。
- 未验证的流量路径推荐只读连接来源/转发路径检查；不自动创建测试封禁。
- 返回子菜单、返回主菜单、无效选项不额外暂停；叶子操作需要留出阅读结果的机会，同一操作只暂停一次。取消、EOF 和破坏性确认语义保持兼容。

## 验证

- 用途保存/加载、组合与冲突、取消/EOF、损坏文件、符号链接及非普通文件。
- 网站、本地中转、落地、远端及组合用途的实际分派；远端不调用本地核心，纯中转不查询 AppSec/HTTP 指标。
- 未选择用途的 CLI 与旧菜单编号兼容；只读检查不产生写操作。
- 使用 PTY 验证首次引导与返回菜单不需要多余回车，防止仅靠非交互管道测试遗漏 pause 行为。
- 相关回归、完整本地 unittest、Bash 语法、既定 ShellCheck 与 diff 检查；完成独立代码审查后同步 main。
