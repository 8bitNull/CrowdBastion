# 已有部署检查与修复

用户已确认将真实 VPS 发现回流至脚本。优先完成统一防火墙检查、日常有效决策入核核对，以及已有部署修复流程。

- 状态检查只读；使用 Bouncer 实际有效配置查询非流式决策接口，不推进 stream 游标、不输出凭据、不跟随重定向。无法完整解释过滤设置时报告未知。
- 共用规则解析及决策覆盖算法，区分服务、启动顺序、入口、决策入核和实际流量证据。未知不能覆盖已确认结构故障。正常空闲地址族不报故障。
- 日常核对只统计仍有至少 15 秒有效期的 ban IP/range，限定当前适用决策类型。集合需被实际执行规则引用，不以所有 ipset 集合的并集代替。未实际公网验收仍保持待验证。
- 已有部署入口先检查，再显示修改范围并确认。沿用锁、私有备份和配置回滚；写入后有期限等待同步。旧规则恢复任务只对明确识别的 root @reboot iptables-restore / ip6tables-restore 项提供逐项停用，保留其他任务，不删除快照，不停用未知服务。
- 不新增依赖，不自动安装、切换后端或重启 Docker/VPS。保留已有 CLI 和菜单编号。现场源码改动与备份必须保留。
- 仓库验证通过后同步至授权 VPS，先只读复查；已有配置健康时不执行重复修复。
