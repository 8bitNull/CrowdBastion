# 菜单流程收敛设计

用户已确认本轮范围：保留四入口首页，让网站、本地中转、远端执行和 V2bX 落地用户能够顺着检查、部署、验证、维护及撤销流程操作。

## 决定

- 沿用现有 Bash/Python 边界、管理锁、确认和回滚，不重写底层安装器，不新增依赖，不改变既有 CLI 语义。
- IP 管理优先依据托管远端连接记录；没有远端记录且仍有本地核心配置时保留本地管理入口，仅更改用途不迁移已有部署。无本地核心配置的远端用途进入远端执行菜单，读取本机状态，提供中心命令说明、路径及验收，不调用本地 cscli。配置损坏时报错，不猜用途。
- 网站向导第 2 步先询问宿主机、Docker host 或 Docker bridge。bridge 明确按检测引擎、私有端点、拦截组件、请求验证排列；端点登记依赖运行中的检测引擎，不能简单挪到引擎之前。增加仅配置引擎的内部调用模式，既有 CLI 仍保留接入选择。
- V2bX 向导进入完整四步菜单，准确命名日志样本分析；提供现有观察配置格式和准备说明，再复用现有安装入口。模板只显示，不写文件或覆盖配置。
- 基础修复追加防火墙维护入口，保留既有编号；追加网站撤销说明入口，明确宿主机需按上游方式撤销，避免暗示已有自动卸载功能。
- 菜单基础规则补齐结合用途及现有部署选择集合；本地中转仅在确认没有网站部署时使用系统/SSH 集合，自定义采集中的 Nginx、Nginx Proxy Manager 和 AppSec 也视为网站部署。配置无法解析时停止补齐。托管远端节点或无本地核心配置的远端用途进入规则菜单时提示在中心维护。CLI `--reset-baseline` 保持原网站集合语义。
- 保留首页快捷入口和高级管理重复入口。各菜单取消或 EOF 不触发后续修改。配置和验收的实际能力边界不变。

## 验证

沿用临时目录和系统命令桩，覆盖远端无本地核心、组合用途、损坏用途、bridge 步骤顺序、取消、V2bX 分发、维护锁及规则集合选择；运行既有引导、用途、检查报告和相关工作流回归。真实 VPS 安装、网络和阻断不在本轮本机测试范围内。
