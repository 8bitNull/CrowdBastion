# 使用体验改进设计

用户在体验审查后要求按建议执行。本设计将已提出的建议落到现有 Bash 菜单及 Python 辅助模块，保持已有部署保护与 CLI 兼容。

## 方案与决定

采用现有菜单增量增强：沿用编号，网站无私有地址步骤时明确标注“不适用”；增加独立 UX 辅助模块处理只读状态、私有配置生成、验收记录和版本指纹。重排所有菜单会破坏既有文档及使用习惯；引入 TUI 框架增加依赖，本轮不采用。

## 行为

- 向导根据磁盘配置及当前服务状态显示“未部署／已配置待验证／服务未运行／状态未知”，不将文件存在或退出码 0 当作实际防护通过。返回及取消明确显示未执行；失败不笼统宣称回滚成功。
- 核心安装在安装依赖、修改配置前显示系统、已有组件、管理员来源、包/配置/服务变更及备份边界，默认取消；已有配置首次选用途后先提供检查。
- 检查页确认执行并成功修改后自动复查；取消、说明和失败留在当前页，原始错误保留。长检查在交互终端显示阶段提示，CLI 输出保持简洁。详情支持可信固定分页器和私有脱敏导出。
- V2bX 以交互方式生成单源配置（已有文件、多源仍受支持），先验证日志、内核、时区、来源网段和目标路径，预览确认后以 0600 原子创建；不覆盖文件或跟随符号链接。
- Docker bridge 显示准备清单及已有端点只读诊断入口，继续复用既有的实际连通性检查，不自动创建网关或公开监听。
- 中转验收保存最近一次结构化记录，含时间、目标、协议、地址族、路径、人工确认边界及配置指纹；检查中展示历史和配置变化提醒，不改变实时健康结论。
- 首页增加固定编号快捷菜单，列出验证、防火墙、通知、验收记录和维护副本，并显示当前用途。深层关键页面带位置提示，旧入口保留。
- 维护副本按脚本和 lib 内容指纹比较；提供确认后同步入口，保留 cron 原文及执行时间，不隐式升级软件包或拉取源码。
- --help 前置常用入口并保留完整参数列表，未知参数仍返回失败；不新增 --help-all。

## 范围及验证

沿用 Python 3、Bash、PyYAML，无新第三方依赖。在当前包含已有修复的工作目录中增量实现，不提交用户既有修改。测试使用临时目录和模拟系统命令，覆盖取消前无副作用、写入安全、复查状态、版本一致性、旧入口兼容。运行完整 unittest、Bash 语法及可用的 ShellCheck。真实 VPS、防火墙和 Telegram 不做部署或发送操作。
