# V2bX 常驻仅观察告警接入设计

用户已授权完成模拟链路、决策隔离、接入／状态／停用入口及真实试点准备。当前阶段只在隔离实验室执行部署测试，不修改宿主机 CrowdSec／V2bX 服务。

独立增量发布服务只读采集器 SQLite，每源最多 256 条／批，带稳定事件 ID 写入一个私有 NDJSON 文件。单独 SQLite 发布账本保存源身份、游标、输出 inode／长度及待提交批次。提交顺序为持久意图、追加并 fsync、提交游标；崩溃后完整批次按哈希确认不重发，零字节批次可继续，部分写入或输出截断／替换必须停止。输出上限 128 MiB，不自动轮转。源库替换、采集契约变更和消费者代际变化必须停止，保留证据等待核对。

不能承诺 CrowdSec 端恰好一次：tail datasource 无逐条持久确认。首次启动用不匹配 parser 的探针确认采集指标增加；发布端正常重启继续游标。消费者不活跃或 InvocationID 改变时停止，不重放已发布事件；该状态需人工对照本地账本与实际告警。采集器在引擎离线时仍可保存未发布事件。

安装现有 parser、仅观察 trigger 与唯一 acquisition，在 profiles 文件最前加入专用场景匹配、空 decisions、on_success break 的 guard。保留原 profiles 原始字节，其他场景继续后续 profiles。先用官方 CrowdSec 1.8.1 隔离验证：在忽略 Remediation 的全封禁兜底下，观察告警零决策，独立对照场景仍可创建决策。

新增启用、只读状态和停用 CLI／菜单；启用需要本地核心和已有采集器。拒绝已存在同名资产、重复 acquisition 通配符、符号链接／不可信路径。修改前留私有恢复记录，安装失败恢复原 profiles、删除仅本轮创建的文件并重启旧配置；恢复失败留证据，不宣称成功。停用先停止发布端，再移除仅本工具规则／采集与 profiles guard，保留账本和 NDJSON，保留既有 SSH／Web 防护。

测试：源追加、采集器重启、rename／copytruncate 指标、发布重启、完整待提交恢复、部分写入停止、积压排空、共享中转／健康排除、三内核官方引擎告警、宽泛 profiles 隔离、安装失败恢复及停用保留。真实 systemd 沙箱／公网协议流量本阶段未验收。
