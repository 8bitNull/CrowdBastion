# VPS167 管理维护优化设计

用户在只读报告后授权“按照建议优化调整”。采用完整发布目录、受保护备份和维护锁下切换：升级 `/root/crowdsec-1key`，增加一致的日常包装入口和维护 current；完整复制 manager/lib/readme 及 rules/v2bx 资源。禁止更新软件包/镜像、替换 iptables 后端、恢复整表、重启 CrowdSec/Bouncer/Docker/网站、安装 Telegram/V2bX 或改变 AppSec deny。

原地逐文件覆盖容易留下半套代码；自动安装/升级总流程会引入组件变化。因此本轮选择预备完整副本后原子切换，并对仍匹配本轮摘要的代码、入口、指针和 cron 提供精确回滚。原源码目录保持原内容和权限，置于 root0700 备份外层；配置归档仅作审计，不回灌活配置/数据库/offset。

共享 `acquisition_state()` 对仅含正数 whitelisted 的统计项不再要求 reads；有实际读取字段的空闲源仍 pending，有读取无解析仍 fault，只有汇总项仍 pending。验证 whitelisted 的数值类型、非负和有限性。复核发现正式网站/SSH健康已按源筛选，误分类来自只读探针对全量输入的调用；不能把修正宣称为防护故障修复。

Hub cron 先读取原注释与调度、查询其他更新任务，只有停用原因允许且用户本次维护授权适用时恢复为维护 current 的 `--update-hub`，保留现场时间/时区；不在本轮立即执行 Hub 更新。若原配置有明确不可恢复原因，则保留并记录证据。root 整表 restore 两条注释始终保留。

验收：TDD、全仓回归、完整包资源检查、写前保护文件/规则/源码比对；写后服务PID与重启数、容器、配置/Web资源、规则、健康schema、集合覆盖、三站本机首页、自主同步和真实维护锁拒绝。AppSec错误保留观察，不发攻击测试。冷启动、公网真实阻断仍不提升为通过。无提交/推送；独立工作树保留，经核对后同步本轮结果回主工作区，不改写旧封存。
