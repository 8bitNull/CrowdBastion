# Web Bouncer 拒绝证据与 Telegram 执行核验

用户已确认 Web 拒绝证据 + TG 核验按钮方案。现有决策通知仅报告检测结果，缺少执行证据。

## 数据与边界
固定版本 vendor 的实际 ban 分支写入请求私有 ngx.ctx，区分 lapi_ban、appsec_rule、appsec_failure、appsec_body。log 阶段只在最终拒绝状态与预期一致、未访问业务上游、主请求时输出结构化记录到 Nginx error log。请求 ID 由 Nginx 生成；不采信客户端 ID/标记，结构化证据字段及 TG 核验输出不含 URI、UA、密钥；沿用的 Nginx error log 仍会自动附原请求上下文（含 URI），遵循该日志既有权限与轮转。保留 1Panel 原日志逻辑。普通 upstream 403、模拟、未命中、故障放行不生成拒绝证据。

兼容已支持 LAPI 故障策略的 vendor 时，额外记录 lapi_failure；升级现有安装不增设或切换故障策略。生产回执从升级后的请求开始生成，历史请求不补录。本期只证明实际 ban 4xx/5xx，不包含重定向、验证码/挑战和防火墙 DROP。

Python 只读解析配置的日志目录中的有界日志尾部，校验日志来源格式、字段、时间、IP、状态和请求 ID；报告观测条数而非全量计数。缺失日志/模块异常与零命中分开。沿用 Nginx/NPM 的日志轮转；报告查询窗口和采样边界。默认 NPM 日志路径，其他部署可配置 execution_log_dirs。

TG 取证卡增加执行核验按钮。核验卡分别展示当前来源 IP 决策和 Web 拒绝证据、拒绝原因、最后时间/ID。只按来源和时间窗关联，明确不能证明原触发请求或某条决策的执行。模拟告警不得获得本告警已执行结论。无证据显示尚未观测到，防火墙实际丢包不在本次核验范围。回调先鉴权和确认，再读取、编辑原卡；刷新不发新消息。

官方实时推送保留异步事实边界，文字引导 /inspect 查询；不自动向 Telegram 发送测试消息，也不引入第二个轮询实例。

## 安装与升级
新安装生成 log.lua 和隔离命名的 execution Lua 模块。既有安装升级须先核验 mount、所有资源哈希、有效请求钩子；仅替换受管理钩子/vendor 文件和新增记录模块，保留 bouncer.conf 和故障策略/账号。升级和 VPS 部署有备份、语法验证、失败回滚和单实例检查。机器人辅助 Python 文件纳入安装备份、归属检查和清理。

## 验收
真实 Lua Nginx 请求验证 LAPI ban、AppSec rule、AppSec fault deny、正常/故障放行、业务403与伪造标记；核对响应、业务上游计数和记录。Python 验证证据校验/边界、TG 鉴权/回调确认顺序。VPS 使用独立 loopback Nginx 验证，生产只做配置核验与受控重载，不封禁管理出口，不声称已验证公网/CDN路径。
