# 工作流等待优化设计

用户要求继续已确认的测试收敛工作。本轮根据上轮逐项耗时和本轮 cProfile，仅优化三个使用假进程/命令、却等待真实 10 秒的业务回归：RealIP reload 失败回滚、宿主机 Bouncer 回滚拒绝清理、worker 在第二次采样前消失。两项真实 10 秒截止时间/挂起查询测试保持原样。

抽样两项 Workflows 测试中，setUp 共 0.038 秒，5 次 run_shell 共 9.850 秒，因此不引入源文件缓存、共享临时树或批量重写夹具。相比缩短生产截止时间或默认全局替换时钟，采用仅三个用例显式追加的测试辅助函数 `virtual_reload_clock()`：nginx_monotonic_us 读取每个夹具独立的时钟文件，sleep 仅推进该时钟，文件使 shell 子进程/命令替换共用同一时间线。保留真实重载验证器、PID/日志解析、回滚逻辑和原断言。

不修改任何生产文件、真实网络实验、默认夹具时钟、测试分层清单或历史审计材料。新增少量辅助函数契约测试，确认子 shell 时间一致、非法 sleep 不推进时间，以及有效重载仍需真实日志与 PID 证据。保留所有原测试 ID；三个测试方法只修改时钟注入，其余源码哈希不变。
