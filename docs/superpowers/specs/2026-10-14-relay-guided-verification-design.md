# 中转引导验收设计

用户已确认按中转优先的方向补齐验证流程、明确结论，并串起安装后的检查。

## 范围与依据

复用中转菜单、健康总结和 nftables Bouncer 配置。新增交互式 `--verify-relay`，结合操作者在独立设备完成的真实新连接测试与本机只读防火墙证据。先支持 nftables 的直接 INPUT/FORWARD 链；Docker bridge、不确定来源或无法识别的规则保留未完成。TCP/UDP 分别验收，UDP 必须使用已有业务客户端获得应用响应，不能把无响应数据包当作正常连接。

## 流程

1. 声明目标单个 IP、入口端口、TCP/UDP、INPUT/FORWARD、独立测试来源与正常对照来源。核对当前管理来源，拒绝共享来源、管理来源和地址族不一致的测试。
2. 读取 Bouncer 配置及规则，确认本次测试来源尚未在适用封禁集合内。操作者确认两个来源均能正常访问同一入口。
3. 生成唯一测试原因和 2 分钟决策命令，明确在本地核心或远端检测中心执行。脚本不运行命令，不读取远端密钥，也不按 IP 删除决策。
4. 在决策同步后读取来源集合及计数；操作者确认测试来源的新连接失败、正常来源仍可达；核对所选链相同规则的计数增加和测试来源仍在集合内。
5. 提示等待该测试决策到期，核查来源已不在集合，再确认双方恢复。取消、EOF 和失败都提示本次短时决策的到期与恢复处理。

## 结论

输出一次“本次入口验证通过（人工确认）／本次入口验证未通过／验证未完成”，显示目标、端口、协议、地址族与声明路径。通过需要全部连接对照完成、封禁集合加入与退出、匹配规则计数增加。外部测试是人工确认；集合计数可能包含其他流量，不单独作为通过依据。结论只适用于本次新连接入口，不更新静态检查为全节点防护通过，不证明 UDP 无响应、既有长连接、网站 AppSec 或专用行为检测。

## 集成与验证

中转菜单添加第 3 项，健康总结验证方法提供向导入口；中转安装完成后自动进行只读服务／防火墙检查，并在终端提供向导选择。远端接入完成后的检查不访问本地 cscli/LAPI。自动检查异常不改写成功安装的退出码，而单独说明运行结果。

使用临时配置、受控命令和交互输入覆盖通过、失败、缺证据、计数重置、来源变化、IPv6、来源集合后缀、取消和远端模式。不得部署生产节点或在本机创建测试封禁。真实 VPS 验收需要操作者在目标节点及外部设备运行向导。
