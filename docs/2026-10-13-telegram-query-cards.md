# Telegram 查询卡片与实际拦截证据

本轮优化自定义交互机器人，官方自动通知继续负责推送。封禁名单和站点体检均为用户发起的只读查询。

## 封禁决策

使用 `cscli decisions list -l 50 -o json` 的告警数组，读取其 `decisions`；`-l` 限制的是告警数量，不能视为决策总量。沿用 CLI 默认来源范围，不包含 CAPI。页面注明查询范围与本次结果，不能代替全局封禁统计。

按 `(scope, value)` 分组，每页 5 个目标；保留每条决策，详情每页 5 条，展示规则、来源、类型、剩余时长、模拟状态与告警 ID。首页显示第一条决策，重复项提示查看详情。Range/CIDR 不提供 IP 解封按钮；IP 解封明确删除该 IP 的全部决策。取证按钮读取告警事件与 ASN/归属信息；这些历史告警附带的决策不应替代当前有效决策列表。

翻页、刷新及返回列表编辑原消息；每次重新查询，决策过期或新增时排序和页数可能改变。消失的目标说明可能过期或超出查询范围。查询失败与空结果分开报告，字段 HTML 转义并限制展示长度。

## 站点体检

每页 5 个 Docker 容器，包含停止的容器。展示运行状态、Docker 状态摘要、HEALTHCHECK 和启动时间；未配置 HEALTHCHECK、状态查询失败均明确报告。只读取摘要和 `.State`，不展示完整 inspect、环境变量或密钥。

按 CrowdSec 配置文件所在目录读取 `crowdsec-1key-web-installs.json`，对选中容器的主配置文件计算 SHA256，与安装记录比较。此检查仅证明主配置文件指纹一致，未检查容器挂载、Bouncer 资源文件或运行时加载。不在记录中的容器显示“无本工具安装记录”，不推断没有外部 Bouncer。其他接入方式尚未核验。HTTP 可用性显示“尚未验证”，首版不访问业务 URL。

## 如何验证 Bouncer 实际拦截

当前“取证穿透”的告警数据来自 CrowdSec，不含请求级的 Bouncer 执行回执。不能直接将“本通知未验证 Bouncer 实际拦截”改成“已拦截”。官方自动通知同样可能在执行决策前送出；日志型检测产生决策时，触发告警的请求可能已经到达后端，决策只影响后续请求。AppSec 可以在当前请求中拒绝，但仍需执行端证据。

要让某条取证显示“已验证”，需要先接入可信的请求级证据采集和关联：

1. 从专用外部测试客户端请求明确授权的测试 URL，携带唯一探针标记。先确认正常请求能到达后端，保留真实来源 IP、UTC 时间、方法、路径和 UA。避免用 VPS 自身或管理连接作为封禁来源。
2. 在实际入口记录服务器生成的 request ID、经过可信代理链解析的真实来源 IP、方法/URI、时间，以及 Bouncer 明确的 deny/ban 执行结果。不能直接信任客户端传入的请求 ID；日志仅有 HTTP 403 时，无法排除 CDN、业务或其他 WAF 拒绝。
3. 检查后端在同一标记与时间窗内没有收到请求，并确认后端日志正常工作且正常对照请求已记录。若是 Firewall Bouncer，入口 HTTP 日志通常不存在，应使用来源/目的地址、协议和端口关联防火墙 trace/对应 DROP 规则计数与后端证据。
4. 将执行记录关联到相同告警及请求，保存组件、执行时间和证据引用；只有匹配成功的请求可显示“已验证 Bouncer 拦截”。聚合告警有多个请求时，应标明验证的样本和数量，不能用一次成功测试认定整个告警都被拦截。

受控链路验收与生产告警验证是两个结果。当前项目的隔离 OpenResty/Bouncer 验收已有 403 且后端未收到探针的记录，但它不证明用户 VPS 的这条告警。服务 active、Bouncer 最近拉取时间、配置一致、有效决策、累计计数、真实 IP 验证记录都不能单独作为该请求的执行回执。本轮没有新增生产证据采集器或自动攻击探测，因此保持诚实的未验证状态。

## 更新已有机器人

在 VPS 更新完整项目后执行：

以下目录为新检出的示例；已有安装请进入原项目目录，更名不要求移动目录。

```bash
cd /home/CrowdBastion
git pull --ff-only
sudo bash crowdbastion.sh --custom-bot
```

选择 `1. 配置/更新并启用`，安装器更新托管文件并重启 `crowdsec-1key-bot.service`。请保留原 Token、Chat ID、管理员 ID 和路径配置。仅重启服务不会把仓库新版复制到安装路径。若实际运行的是自行部署的 `/usr/local/bin/crowdsec_bot.py`，先按原文档识别和停用它的真实启动入口，再迁移；不要猜测 `crowdsec-bot.service` 一定存在。
