# 一键脚本的最终优化边界

适用对象：`install-crowdsec-1panel.sh` 及同目录 `lib/`。基线日期：2026-10-11。

脚本定位为 **Linux 宿主机上的 CrowdSec 安装、接入、验证和维护工具**。达到下面的支持条件与验收标准后，功能进入维护阶段；后续优先修复缺陷和已支持环境的兼容问题。增加新部署体系、修改网站架构或扩大信任范围，需要另立需求并增加相应验证。

## 1. 支持范围按运行能力确定

“支持”表示通过预检后可以管理指定配置，不代表某品牌的所有版本都已经在生产环境验证。

| 环境 | 自动接入范围 | 必须满足的条件 | 超出范围时的处理 |
| --- | --- | --- | --- |
| 1Panel OpenResty | 已验证的 1pwaf 三阶段组合，保留原 WAF 和日志钩子 | 可写持久化目录；实际有效钩子符合已知布局；host 或已登记的私有 bridge 端点 | 未知 WAF/Lua 布局停止合并，保留现有服务 |
| 科技lion LDNMP | 日志采集、规则和 Firewall；兼容 Lua 后可接入 Web Bouncer/AppSec | HTTP `conf.d/*.conf` 已加载且持久化；实际具有 Lua 模块；网络满足接入条件 | 默认无 Lua 的 Nginx 保留日志/Firewall 路径，明确说明 AppSec 尚未接入；不替换镜像 |
| NPM | 持久化 `http_top.conf` Web 钩子；`server_proxy.conf` Proxy Host 真实 IP 配置 | 实际 Lua 能力；`/data` 可写持久化；相关 include 已加载；无覆盖访问钩子或 `satisfy any` | 生成站点文件不作为修改入口；发现冲突、配置漂移或入口缺失即停止 |
| 宿主机 Nginx/OpenResty | 已有官方 Bouncer 接入；标准 Debian/Ubuntu 软件包首次安装；宿主机日志发现、真实 IP 修复与正常请求核验 | 标准服务/默认配置路径；首次安装依赖已就绪且 apt 计划仅涉及 Bouncer 包；真实 IP 使用已加载的标准 HTTP conf.d；核验使用唯一官方 inline 钩子 | 自编译、自定义启动路径、其他 Lua/WAF 钩子或安装计划修改其他包时人工接入 |
| Docker host 网络 | 使用宿主机 loopback LAPI/AppSec | 引擎已运行并具有匹配监听，配置与挂载可核对 | 监听或凭据不符时停止 |
| Docker 私有 bridge | 已准备好的同一宿主机私有网关 LAPI/AppSec 接入 | 明确 IPv4 网关和不同端口；匹配当前连接的 bridge NetworkID/IPAM；宿主机精确监听；容器可达；Bouncer 密钥通过 LAPI 认证 | 不推测 `docker0`、不自动改网络/发布端口/安装转发器；IPv6 bridge、overlay、macvlan、共享容器网络及远程 LAPI 不在此自动入口内 |

基础要求为 root、Bash、systemd、Python 3/PyYAML；WebUI 另需 Docker Compose，Hub 定时维护另需 cron/crond。核心具有 Debian/Ubuntu 和 RHEL 系列分支，发行版软件包是否可用由实际软件源与版本决定。本机已经验证 Debian 13 / 1Panel，其他发行版分支不能据此标记为生产通过。

私有 bridge 端点通过 `--configure-docker-endpoints` 登记，记录与容器名称及 NetworkID 绑定。容器重建可以复用相同持久化挂载和原网络；网络重新创建或端点变化时必须重新核对。这个入口管理端点记录与 Bouncer 接入，**端点监听、转发和防火墙放行由部署者管理**。登记前的 HTTP 探测仅证明连通性，安装时的 LAPI 探测验证凭据；两者都不能代替实际 AppSec 请求验证。

## 2. 自动修改的配置所有权

| 脚本负责 | 所有权与停止条件 |
| --- | --- |
| 核心安装及基础集合 | 仅补缺失软件包/集合；保留已装版本、软件源、自定义规则、白名单和宿主机身份 |
| 日志修复 | 优先读取有效 HTTP 日志指令和实际挂载/宿主机路径，写入本工具管理的采集文件；保留其他采集文件并按覆盖关系去重 |
| 官方 Web Bouncer | 固定版本、校验 SHA256、独立账号、私有密钥和持久化资源；只合并已知钩子；未知 Lua/WAF 逻辑停止 |
| 已有 Bouncer AppSec 地址 | 修改前保存原 URL；仅恢复本工具记录的接入；地址手工变化、只读挂载或生效的 `.local` 覆盖时停止 |
| 真实 IP include | 记录目标、原内容/模式与哈希；保留原所有者；手工修改、挂载漂移、符号链接、单文件 bind 或其他信任规则冲突时停止 |
| WebUI | 本工具容器/Compose、独立 Machine 与数据目录；已拉取官方镜像以摘要固定；失败尝试恢复原部署 |
| Hub 定时维护 | 本工具 cron、稳定维护副本、日志和规则快照；规则更新失败恢复，实时数据库/WAL 不回滚 |
| Telegram | 配置/更新、插件/API 回执测试、只读检查、停用本工具通道；仅迁移目标明确相同的旧 HTTP 路由。可选官方批量通知；检测/决策/实际拦截由 CrowdSec/Bouncer 负责。独立机器人只报告候选，不接管解封/白名单按钮，不卸载未知服务 |
| Console | 明确的注册操作；其他账号和身份保留；实际注册需要使用者选择对应操作 |

不通过批量删除、覆盖未知配置、切换网站镜像、升级整个 Web 栈或重建账号来“修好”检测结果。卸载先检查网站依赖与管理记录；存在 Web Bouncer 或真实 IP 配置时要求先撤销网站接入。维护快照不是完整灾备，不包含网站数据、完整 WebUI 数据或实时封禁数据库的可用恢复方案。

## 3. 真实 IP 与防护证据边界

真实 IP 修复要求用户明确代理链路、唯一 Header 和可信来源。Cloudflare 模式读取官方 IPv4/IPv6 网段；XFF 模式需明确选择并按可信代理从右向左处理。未知 CDN、Cloudflare Tunnel、本机/内网中转不能因为 Header 存在或 DNS 指向某厂商就自动加入信任。

HTTP real-IP 指令只接受明确 IP Header，不直接解析 RFC `Forwarded`。既有站点级覆盖、非标准日志格式、变量日志路径、stdout/syslog-only 日志及无法读取的日志不算自动核验通过。读不到必要证据时保持“尚未验证”，并保留人工核对入口。

`--verify-real-ip` 与 `--verify-host-real-ip` 只对一个受管理的站点根地址发送或等待一次带随机标记的正常请求，关联访问日志和真实 `cs.Allow` 入参。原 WAF 仍先运行；只为该标记记录 IP 诊断，结束后恢复钩子。宿主机还绑定 Bouncer 主配置/`.local` 的哈希；所有证明绑定有效配置与钩子，保存 24 小时。

日志有 `buffer` 时必须有可核对的 `flush`，允许最长 115 秒的 flush，核验最多等待 120 秒。没有 flush 或超出上限时停止自动核验，不修改站点日志配置强制刷新。标准 Nginx 首字段 IP 与官方 NPM Client 布局之外的自定义日志格式需要另行适配。

证据分层验收：

1. 服务和监听正常：程序能够运行。
2. LAPI 认证正常：凭据和目标引擎匹配。
3. 日志读取与解析增长：日志检测入口生效。
4. 正常请求日志 IP 与 Bouncer IP 一致：该站点的访客识别已核验。
5. AppSec 计数增长：该请求进入在线检查。
6. 独立外部请求命中特定规则、返回阻断响应且未到达业务后端：该入口的阻断已验证。

低层证据不能替代高层证据，也不能从一个站点推广到所有站点。Firewall、Docker 转发流量、IPv6、CDN/Tunnel 路径和 AppSec 是不同的实际路径，分别核验。普通页面核验不会自动访问攻击路径；健康检查不会通过定时攻击探测制造 Self-Report。

## 4. 维护质量的最终验收线

| 项目 | 完成标准 |
| --- | --- |
| 并发 | 修改入口使用管理锁；Hub 更新、移除与集合安装另共享兼容旧版的 Hub 锁，不能并发写入。管理锁冲突返回 75 |
| 重复执行 | 内容及已记录接入不变时不新增账号、不更新版本、不重启核心、不重复重载 Web 服务、不重复采集日志 |
| 变更失败 | 在网站/引擎校验和重载失败时恢复修改前配置；回滚重载失败则保留新运行配置可能仍需要的账号/资源并提示人工恢复 |
| 凭据 | 私有状态、密钥和可能含密钥的安装日志仅 root 可读；密钥探测通过标准输入配置传递，不放在命令参数或用户输出 |
| 下载与版本 | 原生 Lua 资源固定版本和 SHA256；WebUI 部署固定摘要；Hub 内容可更新且具有独立快照/恢复能力 |
| 状态 | 异常返回 1、证据缺失返回 2、锁冲突返回 75；普通操作成功为 0；有效 HTTP 响应不能单独算防护通过 |
| 回归 | 四类部署布局均覆盖首次/重复/取消/漂移/失败/撤销；Lua、真实 IP、NPM 继承和日志缓冲必须有实际运行时验证 |
| 生产保护 | 验证结束后临时钩子、测试账号、测试容器/网络及测试专用防火墙规则清理；不对生产站点自动发送攻击请求 |

Hub 更新、集合安装及移除共用持久快照、锁、校验和加载事务，恢复前拒绝快照损坏和外部文件冲突；集合安装在最终核心加载成功后提交。系统软件包安装及网站重载不是完整原子事务：软件包和必要依赖可能保留，正在处理的请求、异步旧 worker 和 apt 副作用不能依靠文件回滚完全撤销。验收要求说明实际恢复结果和剩余动作，不承诺任何故障都能全自动恢复。

## 6. 达到边界之后如何维护

允许继续优化：可复现缺陷、明确的新版本兼容变化、已支持布局的日志路径补充、只读诊断准确性、回滚和权限缺陷、测试补缺、文档与代码一致性。每次更改先说明触发条件与行为变化，再运行对应回归；涉及 Lua/代理继承/网络时加入真实运行时验证。

纯中转节点新增范围：`--install-relay` 只补齐系统/SSH 规则与文件/journalctl 采集，`--relay-status` 只读核查 INPUT/FORWARD、IPv4/IPv6 规则引用；已有 Web/AppSec 配置保留，详见 [中转模式](relay-mode.md)。不管理转发器、NAT、限速，也不宣称静态检查证明业务阻断。

需要新需求：自动安装/管理 LDNMP/NPM 栈、改造现有网站镜像、全自动代理链识别、管理 Docker/面板防火墙与私有转发器、中转专用日志解析/行为检测与连接限制、远程或集群 LAPI、Kubernetes、非 systemd/非 Linux 环境、自动迁移数据库、性能自动调参和无人值守生产攻击探测。

停止优化的标准是：**支持范围明确、操作可重复、失败可追踪、受管理配置可恢复、验证结果能与真实链路对应。**不以“功能无限增加”“兼容任意环境”或“已经没有任何 bug”作为最终目标。
