# 仓库发布范围与本地归档

远程仓库保存安装、使用、维护和回归所需的文件。本地工作过程与生成产物由 `.gitignore` 排除，留在原路径，不执行物理删除。

| 内容 | 处理方式 | 用途 |
| --- | --- | --- |
| 主脚本、兼容链接、`lib/`、`tools/` | 提交并推送 | 安装与运行 |
| `tests/`、依赖清单、测试分层清单 | 提交并推送 | 在新克隆中发现和运行回归 |
| 使用指南、协议来源、`rules/`、`experimental/` | 提交并推送 | 公开说明、规则样板与固定版本实验补丁 |
| `docs/audit/` 顶层 Markdown 报告 | 脱敏后提交并推送 | 验收结论、失败记录与覆盖边界 |
| 审计 JSON、日志、终端输出、临时脚本、源码副本、补丁快照、校验清单 | 仅在本地原路径保留 | 历史调查与复现材料；下述测试依赖除外 |
| `docs/superpowers/`、旧安装设计与计划、Telegram 文案草稿 | 仅在本地原路径保留 | 内部工作计划与过期草稿 |
| `.venv/`、`.superpowers/`、缓存、编辑器状态、覆盖率与扫描输出 | 仅在本地保留 | 开发环境与生成产物 |
| 凭据、私钥、数据库、原始运维信息 | 仅在本地或仓库外保留 | 不得发布；遵守 [敏感信息政策](../SECURITY.md) |

## 回归依赖例外

以下三份文件仍在原路径公开跟踪，避免改变既有测试的输入或覆盖范围：

- `docs/audit/2026-11-02-vps45-repair/scripts/static-policy.py`：`test_vps45_static_policy.py` 直接测试的静态规则脚本。
- `docs/audit/2026-11-02-vps167-optimize-review/scripts/rollback-manager-v2.py`：`test_vps167_rollback_review.py` 直接测试的回滚模板。

这两份节点脚本属于历史回归对象，不是通用安装入口，不应直接用于其他生产节点。新增共享样本应优先放入 `tests/`，并使用合成或脱敏数据。

## 本地归档的使用

历史报告中标注“本地归档”的路径只在保有原始材料的工作区可用；新克隆不包含这些文件。旧命令中的本机 `/tmp` 资源和环境脚本也需另行准备。公开报告描述当时的验证结果，不等于新克隆已经完成相同验收。

2026-11-04 整理时，将 1,449 份历史材料取消 Git 跟踪并保留于本地。原路径、文件大小与 SHA-256 清单保存在本地 `private-audit/repository-cleanup-2026-11-04/local-files.json`，不随远程发布。

不要使用 `git clean -fdx` 清理这些归档；该命令会删除被忽略的文件。再次添加文件时使用明确路径，并先检查 `git diff --cached --stat`。修改 `.gitignore` 不会自动移除已跟踪文件，需单独取消跟踪。

本次只改变后续版本的发布范围，不重写远程历史，也不会缩小已有克隆的 Git 对象库。历史提交和 PR 引用的敏感信息处理仍遵守 [敏感信息政策](../SECURITY.md)。
